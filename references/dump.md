# 倾倒 · 从各端把原料抽出来

## 为什么自述是主通道

各端的记忆导出能力差别很大，而且一直在变——今天能导出的功能明天可能改了入口。但有一件事每一端都能做：**你可以直接问它"你记得关于我的什么"。**

自述和文件导出拿到的东西不一样：

- **文件导出**给你的是存储里躺着的全部条目，其中相当一部分从来没被召回过。
- **自述**给你的是模型**此刻实际调得到**的记忆。

自述是主通道，因为它是唯一跨端通用的——不管哪一端、不管它的导出入口今天改没改，你都能直接问它。

**但别把"没被召回过的条目"当成无害。** 一条今天召不回的记忆，明天在某个场景里召回了，就是一次跨端偏差——它不是零影响，是延迟引爆。所以**文件层导出值得跑，不是锦上添花**。

**但它需要用户授权，不是默认动作。** 文件层记忆、会话历史、用户自建的笔记库都是他的东西，读之前要问，问清楚读哪些、不读哪些。按授权范围和该端实际能力启用——**别把"能读到"当成"应该读"**。

不过自述有个已知的失败模式：直接问"你记得我什么"，模型倾向于产出一段得体的、正面的、概括性的小传——把负面的、具体的、尴尬的部分磨平了。而档案里最值钱的恰恰是那些：用户否决过什么、什么话题会让他上火、他讨厌被怎么说话。所以要用 `assets/prompts/self-report.md` 里那份 prompt，别自己临时编一句。

## 操作流程

### 1. 列端

跟用户确认在用哪些端，标出主力与偶尔用。主力端必须倾倒，偶尔用的端可以只做一次自述。

### 2. 每端跑一遍自述

**主路径：这一端自己把结果写进信源的 inbox。** 只要它写得进（本地端直接落盘、GitHub connector 能提交、filesystem MCP 能写），就让它自己交作业。这是自动化的前提，也是让倾倒时间对得上使用时间的前提——见 `consolidate.md` 为什么这件事影响裁决。

**写不进锚点的端，接入未完成。** 它可以读统一结果（属于只读消费者），但没有完成双向同步——不要把"用户每次手工复制粘贴"写成日常通道，那正是他最初要摆脱的工作方式。手工搬运只用于首次诊断和授权受阻时的临时恢复。

**用哪份 prompt 看场合：**

| 场合 | 用哪份 |
|---|---|
| 基线倾倒（端首次纳入） | `assets/prompts/self-report.md` —— 深挖，七类全过 |
| 日常增量 | `assets/prompts/self-report-incremental.md` —— 只要变化 |

日常每次都跑完整基线，产出的绝大部分是上一轮已经有的内容，噪音和重复都跟着涨。

**在当前这一端，你可以自己跑**——但要跑得诚实：按那份 prompt 的要求，把"我记得的"和"我从当前这次对话里现推的"分开写。混在一起，冲突消解那步就没法工作了。

### 2a. 知识资产动作不是原生记忆

自述新增的知识资产类回答“这一端可以确认自己在会话之外创建或改动过什么”，不是“这一端把用户什么信息存进了原生记忆”。交包时把它放进 `## 非原生记忆来源 / ### 已创建或更新的外部知识资产`，不要混进 `## 可访问的持久记忆`。

- `[操作]`：当前会话或工具记录能确认；这是优先证据。
- `[记]`：只有本端跨会话记忆记得，当前看不到操作记录；保留这个较弱来源。
- `[推]`：不接收。推断“应该写过一份”不能建立资产路由。

只收被明确当作跨会话、跨任务参考物保存的资产。普通项目实现、代码修改和当前工作区里本来就能定位的交付物继续由项目文件与动态信源路由负责，不进知识资产区。

倾倒物按端分开存，不要合并。文件命名带端名和日期，例如 `dump-chatgpt-20260809.md`。整合那步需要知道每条来自哪一端。

### 2c. 交进 inbox 的规矩

格式、命名、frontmatter 字段都在 `protocol.md`，这里只讲操作上最容易做错的三条。

**每个端只写自己的收件区**（`dumps/inbox/<endpoint-id>/`），而且只新建、不改旧的。端与端之间因此没有写冲突，不需要任何调度协议。

**包不可变，新包不淘汰旧包。** 同一端连着交了三个包、前两个还没被消费，三个都留在候选集里，一个都不能动。

理由反直觉但很硬：**自述倾倒不是数据库快照，是概率性召回。** 同一端第二次可能想起 A、却忘了第一次吐出的 B。新包不能证明包含旧包——按"新的覆盖旧的"处理会把 B 静默丢掉。去重在**条目层**做，不在文件层做。

包什么时候算处理完，只有一个判据：**它出现在某个已成功发布版本的消费 manifest 里**（`dumps/processed/manifest.md`）。

**没新增就不交包。** 交之前拿倾倒结果跟"我上次读到的统一版本"比一遍，完全没有新增就别产包。这一步各端自己做得了，统一版本本来就在它上下文里。空包只会让后面每一轮合并都多嚼一遍。

**倾倒时间不裁决事实新旧。** `captured_at` 和 `trigger` 只用于审计。所以**采集时要多要条目级的时间信息**：原话是什么时候说的、事实什么时候发生的、有没有取代关系。这些才是整合时唯一能用来裁决的东西——这一步多问一句，那一步少一条待确认。

### 补交：游标驱动的恢复路径

用户上次在这一端干完活忘了同步，下次追平时游标会露馅：**`state/endpoints/<id>.md` 记着上次读到 v5，却没有对应的倾倒包。** 这时补一个。

**这是恢复路径，不是常规步骤。** 正常流程里状态机的第 2 步就把它办了。

### 2b. 追问一轮，别拿第一轮当全部

自述几乎从来不是一次问完的。两个动作：

**一、问它倒完了没。** prompt 结尾那句"这是全部还是还有更多"要真的读它的回答。答"还有"就再跑一轮，让它接着列。

**二、对写"无"或只有一两条的类别单独重问，换个问法。** 最容易垮的是第 4 类（负面项）和第 5 类（沟通偏好）——而这两类恰恰是 `routing.md` 的主料。泛泛问"我的沟通偏好"它答不出来；具体问"我有没有纠正过你的说话方式？哪一次？我当时原话大概是什么"，它就能捞出来。

追问的产出跟第一轮存在一起，标明是追问所得。

### 3. 抓文件层的原生记忆

自述之外，各端还有落在磁盘上的记忆。**下面这些位置要实际去看，别假定存在**——各端的路径和机制都在变，找不到就说找不到，不要编一个路径出来交差。

| 端 | 去哪找 |
|---|---|
| Claude Code | `~/.claude/CLAUDE.md`（全局）、各项目根的 `CLAUDE.md`、`~/.claude/projects/` 下的会话历史、用户自建的记忆目录 |
| Codex | 仓库根与上层目录的 `AGENTS.md`、`$HOME/.agents/`、`~/.codex/` |
| Claude.ai / Claude Desktop | 设置里的记忆相关条目（入口位置会变，让用户自己找并截图或复制）；项目自定义指令 |
| ChatGPT | 设置里的个性化 / 记忆管理；自定义指令；ChatGPT 的数据导出功能（如果用户愿意等） |

**本地端的记忆不是一份文件，是一棵树。** 全局指令、用户自建的记忆目录、每一个项目根下的 `CLAUDE.md` / `AGENTS.md`——都要遍历，别只看全局。

而项目级那一层是被漏得最狠的富矿：**用户对 AI 说话方式的纠正，几乎总是发生在某个具体项目里**，被写进那个项目的指令文件，全局永远看不见。那些条目已经被用户手工提炼过一次，浓度比会话史高得多。

**用户自建的记忆系统按该端原生记忆对待**（比如一个记忆目录加一份索引文件）。它是倾倒源，后面也是写回目标。不要求用户改造它的结构，也不试图取代它——它挂在 harness 层、每次会话自动加载，这个地位知界拿不到也不该抢。

**已有的 profile / persona 文件也在这一步收进来**，当成"某一端的倾倒物"平等对待，不给它特权。它的年龄往往比看起来大。

### 跳过知界自己写过的东西

倾倒时会撞见知界上一轮装进去的内容——受管区块、指令位里的只读投影、写回全局文件的条目。**看见知界的生成头就跳过**，别把自己写的东西当成"这一端记得的"收回去。

包的 frontmatter 里如实填 `contour_context_loaded` 和 `last_contour_revision_read`（见 `protocol.md`）——整合那步靠它们识别回声。

三道防线，从弱到强：生成头（会被平台改写或吃掉）→ frontmatter 元数据（端自己填，可能填错）→ **整合时的差集**（不依赖任何标记，见 `consolidate.md`）。前两道省事，最后一道兜底。

### 3b. 用户自建的记录（证据强度最高的一类）

很多人有自己维护的项目库、工作日志、待办系统、笔记库（Notion / Obsidian / 飞书 / 日历……）。**这些不是 AI 记忆，但它们是最好的原料，值得专门问一句用户有没有。**

因为它们是**行为痕迹，不是印象**。模型自述给你的是"它以为用户是谁"，自建记录给你的是"用户实际把时间花在哪、实际完成了什么、什么事反复出现又反复搁置"。证据强度高一个量级。

尤其值得抽的两类：

- **时间分配**。带日期的记录能看出精力实际投向哪里。而人对自己的自述几乎总是偏向**意图**而非**行为**——`profile.md` 写着"重视 A"，记录显示三个月都在做 B，这个矛盾是极高价值的证据，任何模型自述都产不出来，因为没有一端看得见用户的时间分配。这类矛盾不要消解掉，原样写进 `evidence.md`，它同时支持"他声称的优先级"和"他实际的优先级"两条结论。
- **反复搁置的事**。一件事进了清单五次没做，说明的东西比它做完了更多。

**只读，单向。** 这些系统归用户的工作流管，知界从中抽料，不写回、不接管、不建议用户改它的结构。它们的消费者是用户本人，知界的消费者是模型——两套东西的冗余规则和过期规则正好相反，混在一起会互相破坏。

### 4. 抓会话史里的碎片（可选，但价值高）

典型的例子：用户在聊游戏时顺口讲了一段行业剖析，当时看着没有记忆价值，但在求职场景里那是他自己都没意识到的优势。这类碎片**原生记忆系统基本不会留**——它们不像"事实"，所以没触发保存。

如果用户的端能翻会话历史（Claude Code 的 `~/.claude/projects/` 是最好翻的），值得扫一遍找这几类东西：

- 用户在非专业场景里露出的专业判断
- 用户明确否决过某个方案，以及**否决的理由**（理由比结论值钱得多）
- 用户对 AI 的纠正——"别这么说话""你又开始了"。这是 `routing.md` 沟通路由的一等原料
- 用户情绪明显起伏的时刻，以及触发点

这一步开销大。如果时间有限，跳过，在 `now.md` 里记一条待办。别为了做全套把用户拖垮。

## 交付给整合那一步的东西

一组按端分开的倾倒文件，加一份清单：

- 哪些端倾倒了，哪些没有（没有的写明原因：接不到 / 用户不想 / 该端没记忆）
- 每份倾倒物的日期
- 自述里模型自己标注为"现推的"而非"记得的"部分，单独标出来——这些在冲突消解时权重最低
