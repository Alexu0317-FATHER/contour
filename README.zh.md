# 知界 Contour

[English](README.md) | 中文

**给同时用好几个 AI 助手的人做的跨端记忆协调层。**

你在用 Claude Code、Codex、Claude.ai、Claude Desktop 和 ChatGPT——每一端都对你有一份记忆，每一份都残缺、都不一样。换端等于重新教一遍，记忆成了平台转移成本。而且没有任何一端对「该怎么跟你说话」有可携带的定义。

知界解决这个。它**不取代**任何平台的原生记忆：它维护一份你自己掌握的信源，从信源去喂各端的原生记忆，并把一张可携带的路由表放进每一端的常驻上下文，让各端行为逐渐收敛。

## 怎么装

### 一、装技能（你做，一条命令）

```bash
git clone https://github.com/Alexu0317-FATHER/contour ~/.claude/skills/contour
```

VS Code 里的 Claude Code 读的是同一个目录，**装一次两边都有**。

> ⚠️ `master` 上目前还是已归档的旧版产品，新技能在 `chore/clear-legacy-tree` 分支上。合并之前请加 `-b chore/clear-legacy-tree`。

**其他端怎么装**：Codex、Claude.ai、ChatGPT、Zed 各自的技能包安装方式 `[未验证]`，会在接入时实测后补上——不靠印象写别人产品的操作步骤。

### 二、说一句话（你做）

装完之后在任意地方说「**初始化知界**」。

技能会问你在用哪些端、哪些是主力，然后带你建一个私有实例仓、逐端跑基线倾倒。**首版统一档案要求至少两个不同的端各交一份基线**——只有一个端的记忆，合出来的不是跨端档案，是那一个端的复读。

之后日常只需要说「**同步知界**」或「**看下知界状态**」。技能自己读实例仓判断你处在哪一步（追平 / 整合 / 倾倒 / 体检），**你不用交代上下文，也不用记命令。**

### 三、配置文件由技能自己写（不用你动手）

**你不需要手动编辑任何 `CLAUDE.md` 或 `AGENTS.md`。** 技能会：

- 往**全局** `~/.claude/CLAUDE.md` 写一行指向你信源的导入
- 往**全局** `~/.codex/AGENTS.md` 写一段带标记的区块（Codex 不展开 `@路径`，这是实测结论，所以那边贴全文）
- 每次同步之后自动刷新这些内容

**它不碰你项目里的 `CLAUDE.md` / `AGENTS.md`。** 那些文件可能进 git、可能有同事、有项目自己的约定——不该被一个个人档案工具改。

### 唯一需要你动手的一步：给网页端传文件

Claude.ai 和 ChatGPT **没有官方接口**能让程序更新它们的项目文件（第三方同步工具靠 session cookie，过期即静默失效，技能不推荐）。所以每次同步之后，技能会生成一份带日期的 `routing.md` 并提醒你「该传了」，你把它拖进 Project Files / 文件库。

这一步绕不开，但它是**低频**的：这份文件月级变化。**日常的倾倒和读取走连接器，不用你搬运。**

### 它不会先斩后奏

你随口抱怨一句「这 AI 根本不了解我」，技能最多解释一下、问你要不要同步——**连读你的私有仓都不会做**。读、写、提交、合并全都要你明确点头。

各端背后到底用哪种加载机制、为什么这么选、副本怎么防过期，见 [`skills/contour/references/load.md`](skills/contour/references/load.md)。

## 几条设计承诺

- **一个权威锚点，多端可以临时接任协调；单次发布必须串行。** 副本可以有，两个权威锚点不行。读之前追平，写回必须条件化。
- **知界不持有你的记忆，它刷新你的记忆。** 原生记忆系统继续干它的活，知界提供更好的材料和一份可携带的关注策略。
- **收敛要测出来，不是宣布出来。** 不做行为体检，你没有任何理由相信各端在往一起走而不是在往两边散。
- **没有你点头，什么都不会发生。** 技能被触发不等于它可以读你的仓库，更不等于可以写。
