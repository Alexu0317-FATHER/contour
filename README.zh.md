# 知界 Contour

[English](README.md) | 中文

**给同时用好几个 AI 助手的人做的跨端记忆协调层。**

你在用 Claude Code、Codex、Claude.ai、Claude Desktop 和 ChatGPT——每一端都对你有一份记忆，每一份都残缺、都不一样。换端等于重新教一遍，记忆成了平台转移成本。而且没有任何一端对「该怎么跟你说话」有可携带的定义。

知界解决这个。它**不取代**任何平台的原生记忆：它维护一份你自己掌握的信源，从信源去喂各端的原生记忆，并把一张可携带的路由表放进每一端的常驻上下文，让各端行为逐渐收敛。

## 你的东西存在哪

**不在这个仓库里。** 知界会带你新建一个**你自己的私有仓库**，你的画像、倾倒物和证据都住在那儿——这个仓是公开代码，个人材料不该进来。

那个私有仓是你的，不是知界的：你随时可以直接打开看每一条结论、它的出处、以及是哪一端在什么时候贡献的。

## 前置条件

跟别的项目要你先装 git、装 node 一样。**不满足不是"降级运行"，是装不上**——知界会直接告诉你缺什么，不会自己缩水成半残模式。

**一、一个专门存放知界数据的 GitHub 私有仓库。** 已经有专用私仓就直接提供地址，知界先验证隐私、权限和目录结构；没有 GitHub 账号或专用仓库，就从注册、授权到建私仓逐步引导。登录、验证码和授权确认必须由你完成，其余能由 Agent 代办的创建与配置不再甩给你手工操作。**不要复用装有其他项目的仓库**——这里将来会存放你的健康、家庭、职业等私人材料。

**二、每一个纳入的端都要能读写那个仓库。**

| 端 | 怎么满足 |
|---|---|
| **Claude Code / Codex / Zed** | 本机有 git 和该仓库的访问权限就行 |
| **ChatGPT** | 设置 → 插件 → 开启 **GitHub 插件**。Plus 就有，不需要 Developer Mode |
| **Claude.ai Chat / Projects** | 内置 GitHub 连接只负责读取和同步项目知识。当前账号实测中，Chat 的临时代码环境能改文件并本地提交，但没有 GitHub 凭据，不能推送。要双向同步，仍需一条**已经验证可写**的远程 MCP 路径；GitHub 官方远程 MCP 在 claude.ai Chat 中尚未完成接入验证 |

> ⚠️ **Projects 里那个「用 GitHub 当项目知识」不算双向接入。** 它只把仓库文件同步成可检索的知识，不能提交倾倒包。
>
> claude.ai 左侧的 **Code** 标签是 Claude Code 的会话入口。它可以显示或远程控制本地 CC 会话，也可以另起云端 CC 任务；仓库读写能力取决于背后的 CC 会话和授权。它不是普通 Chat，**不共享 Chat 的原生记忆**，所以不能拿 Code 标签里能做的事冒充 Claude.ai Chat 的写入能力。

## 怎么装

### 一、装技能（你做，一条命令）

```bash
git clone https://github.com/Alexu0317-FATHER/contour ~/.claude/skills/contour
```

VS Code 里的 Claude Code 读的是同一个目录，**装一次两边都有**。

> ⚠️ `master` 上目前还是已归档的旧版产品，新技能在 `chore/clear-legacy-tree` 分支上。合并之前请加 `-b chore/clear-legacy-tree`。

**其他端怎么装**：Codex、Claude.ai、ChatGPT、Zed 各自的技能包安装方式 `[未验证]`，会在接入时实测后补上——不靠印象写别人产品的操作步骤。

### 二、说一句话（你做）

装完之后在任意地方说「**初始化知界**」。

技能会问你在用哪些端、哪些是主力，然后带你建一个私有实例仓、逐端跑基线倾倒。**首版统一档案要求至少两个不同的端各交一份基线**——只有一个端的记忆，合出来的不是跨端档案，是那一个端的复读。

之后日常只需要说「**同步知界**」或「**看下知界状态**」。技能自己读实例仓判断你处在哪一步（追平 / 整合 / 倾倒 / 体检），**你不用交代上下文，也不用记命令。**

### 三、配置文件由技能自己写（不用你动手）

**你不需要手动编辑任何 `CLAUDE.md` 或 `AGENTS.md`。** 技能会：

- 往**全局** `~/.claude/CLAUDE.md` 写一行指向你信源的导入
- 往**全局** `~/.codex/AGENTS.md` 写一段带标记的区块（Codex 不展开 `@路径`，这是实测结论，所以那边贴全文）
- 每次同步之后自动刷新这些内容

**它不碰你项目里的 `CLAUDE.md` / `AGENTS.md`。** 那些文件可能进 git、可能有同事、有项目自己的约定——不该被一个个人档案工具改。

### 唯一需要你动手的一步：给网页端传文件

目前还没有为 Claude.ai Chat 和 ChatGPT **验证出**由知界直接更新项目文件的稳定路径（第三方同步工具靠 session cookie，过期即静默失效，技能不推荐）。所以当前流程仍会生成一份带日期的 `routing.md` 并提醒你「该传了」，由你把它拖进 Project Files / 文件库。

在新的官方路径被查证并接入以前，这一步仍是**低频人工动作**：这份文件变化很慢。**日常倾倒和读取只有在当前端已经具备经验证的仓库读写通道时，才能不靠你搬运。**

### 它不会先斩后奏

你随口抱怨一句「这 AI 根本不了解我」，技能最多解释一下、问你要不要同步——**连读你的私有仓都不会做**。读、写、提交、合并全都要你明确点头。

各端背后到底用哪种加载机制、为什么这么选、副本怎么防过期，见 [`skills/contour/references/load.md`](skills/contour/references/load.md)。

## 几条设计承诺

- **一个权威锚点，多端可以临时接任协调；单次发布必须串行。** 副本可以有，两个权威锚点不行。读之前追平，写回必须条件化。
- **知界不持有你的记忆，它刷新你的记忆。** 原生记忆系统继续干它的活，知界提供更好的材料和一份可携带的关注策略。
- **收敛要测出来，不是宣布出来。** 不做行为体检，你没有任何理由相信各端在往一起走而不是在往两边散。
- **没有你点头，什么都不会发生。** 技能被触发不等于它可以读你的仓库，更不等于可以写。
