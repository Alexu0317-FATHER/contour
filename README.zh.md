# 知界 Contour

[English](README.md) | 中文

**给同时用好几个 AI 助手的人做的跨端记忆协调层。**

你在用 Claude Code、Codex、Claude.ai、Claude Desktop 和 ChatGPT——每一端都对你有一份记忆，每一份都残缺、都不一样。换端等于重新教一遍，记忆成了平台转移成本。而且没有任何一端对「该怎么跟你说话」有可携带的定义。

知界解决这个。它**不取代**任何平台的原生记忆：它维护一份你自己掌握的信源，从信源去喂各端的原生记忆，并把一张可携带的路由表放进每一端的常驻上下文，让各端行为逐渐收敛。

## 各端怎么装

装的是一份 `routing.md`（沟通路由 + 记忆关注策略），它是唯一需要每轮都在场的那份；其余按需读。**关键差别不是"支不支持技能"，是"这一端能不能保证 `routing.md` 在模型开口之前就已经在上下文里"。**

| 端 | 装法 | 常驻保证 |
|---|---|---|
| **Claude Code** | `CLAUDE.md` 里写 `@<实例仓>/routing.md` | ✅ harness 确定性展开全文 |
| **Codex** | `AGENTS.md` 的受管区块里贴 `routing.md` 全文 | ✅ 确定性，但是**副本**，每次同步要重新生成 |
| **Claude.ai / ChatGPT** | 传进 Project Files / 文件库，指令位只写一行指针 | ⚠️ **装完当场测**：文件是确定性进上下文，还是按相关性检索召回？是检索就得降级 |
| 以上都不行 | 自定义指令里贴只读投影，带生成日期头 | ⚠️ 副本，实例仓更新后要手动重贴 |

**Codex 不展开 `@路径`**——这是实测结论，不是推断，所以它用受管区块而不是导入。各端的完整装法、三种副本的共同纪律、以及"喂"这一步怎么做，见 [`references/load.md`](references/load.md)。

**装技能 ≠ 常驻。** 技能是渐进式披露的：只有 `description` 一直在，正文要等匹配上任务才加载。所以装技能解决的是"这一端能自己跑完整流程"，不是"路由表每轮都在"——**两件事都要做。**

## 初始化：你只需要说一句话

装好之后不用记命令。说「**同步知界**」或「**看下知界状态**」就够了——技能会先读实例仓判断你处在哪一步（冷启动 / 新端接入 / 追平 / 整合 / 倾倒 / 体检），然后从那一步接着往下跑，不需要你交代上下文。

第一次跑会问你在用哪些端、哪些是主力，然后带你定锚点、逐端跑基线倾倒。**首版统一档案要求至少两个不同的端各交一份基线**——只有一个端的记忆，合出来的不是跨端档案，是那一个端的复读。

**它不会先斩后奏。** 你随口抱怨一句「这 AI 根本不了解我」，技能最多解释一下、问你一句要不要同步——**连读你的私有仓都不会做**。读、写、提交、合并全都要你明确点头。

## 几条设计承诺

- **一个权威锚点，多端可以临时接任协调；单次发布必须串行。** 副本可以有，两个权威锚点不行。读之前追平，写回必须条件化。
- **知界不持有你的记忆，它刷新你的记忆。** 原生记忆系统继续干它的活，知界提供更好的材料和一份可携带的关注策略。
- **收敛要测出来，不是宣布出来。** 不做行为体检，你没有任何理由相信各端在往一起走而不是在往两边散。
- **没有你点头，什么都不会发生。** 技能被触发不等于它可以读你的仓库，更不等于可以写。
