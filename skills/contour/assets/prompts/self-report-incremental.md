# 增量自述 prompt

用于已有基线后的日常同步。将时间与版本占位符替换为实际记录；缺失时注明未知，不编造。

---

导出自上次成功倾倒以来新增或发生变化的记忆，以及可确认的外部知识资产动作。

上次同步时间：`<上次同步时间>`
上次读到的知界统一版本：`<上次统一版本>`

按以下类别逐条列出：

1. **新增**：新获知或本次首次召回的信息；区分事实发生时间与本次召回时间。
2. **更正**：原信息、新信息以及用户更正的时间或依据。
3. **失效**：已经不成立的信息及依据。
4. **重新出现**：最近又与当前情境相关的旧信息。
5. **知识资产变动**：已保存、用于跨会话复用的资产被创建或修改。写清动作、名称、位置、变化范围和时间。普通项目实现、代码修改及当前工作区管理的交付物不计入。

第 1–4 类注明：

- 来源，三选一：`[记:<类型>]`（跨会话可访问的记忆或资料，类型写原生记忆、自定义指令、项目文件或其他具体材料）、`[会话]`（本次对话中我的陈述或我提供的材料）、`[来源不明]`（知道内容但无法确认来源；不猜测来源，也不因此当作推断）。
- 推断：根据上述来源推断出的结论另加 `[推]` 并写出依据；直接来自记录或我的陈述的不加。
- 能核对的用户指令、偏好和纠正原话；无法核对时标为转述。
- 条目时间；不知道时写 `[无时间]`，不以采集日期代替事实日期。
- 对应实体名称，以及是否属于知界已经提供的内容。

第 5 类使用 `[操作]`（当前会话或工具记录可核对）或 `[记]`（仅由跨会话记忆召回）。仅推测存在的资产不列出，缺少的字段标为无法确认。

输出要求：

- 类别无变化时写“无变化”；无法判断时说明原因。
- 保留具体变化及矛盾，不复述无变化的全部记忆，不添加人物评价。
- 选用能完整转存的形式：在聊天中交给我复制时，把全部条目放在一个代码块内；直接写入文件或通过工具提交时，按该通道要求的格式写入。
- 条目之后说明是否还有当前可以继续提供的变化；不声称完整覆盖不可观察的后台记忆。
