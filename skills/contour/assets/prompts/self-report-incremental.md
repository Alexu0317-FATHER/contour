# 增量自述 prompt

日常同步用这份，**不要每次都跑基线**（`self-report.md`）。基线跑一遍产出的绝大部分是上一轮已有的内容，噪音和重复都跟着涨。

用哪份：

| 场合 | 用哪份 |
|---|---|
| 端首次纳入 | `self-report.md`，六类全过 |
| 日常同步 | 本文件 |
| 探测（虚构标记） | 见 `references/probe.md`，另有测法 |

发之前把 `<上次同步时间>` 和 `<上次统一版本>` 替换成真实值——它们是这份 prompt 的全部锚点。

设计说明（不要连这段一起发）：

- **"变化"要展开成五类**：新增、更正、失效、重新出现、产出物变动。只说"有什么新变化"会漏掉后四类，而更正和失效恰恰是最该收的——它们是让各端摆脱旧错条目的唯一来源。
- **第 5 类必须每轮都问。** 资产路由最隐蔽的腐烂方式是：某一端往一份已登记的文档里补了一节，指针还对、页面还在，但 `覆盖范围` 和 `最后验证` 已经旧了，而没有任何人会来告诉那张表。这一类是唯一的上报通道。
- **仍然要 `[记]` / `[推]`**。增量场景下模型更容易把"这次对话里聊到的"当成"记住的"。
- **"没有变化"必须是一个允许的答案。** 没给它这个出口，模型会为了填满格式硬凑，凑出来的东西会被下游当成新证据。
- 不要求它回顾全部记忆，只要求它对照上次同步。这也是为什么必须填真实的时间和版本。

---

这是一次增量记忆导出，不是一次对话，也不是让你复述全部记忆。

上次同步时间：`<上次同步时间>`
上次你读到的知界统一版本：`<上次统一版本>`

**只列自那之后发生变化的部分。** 没有变化的类别写"无变化"，不要为了填满格式硬凑。

五类变化分开列：

1. **新增** —— 那之后我新告诉你的、或你新记住的
2. **更正** —— 我明确纠正过的旧信息（**写清楚：旧的是什么、新的是什么、我大概什么时候纠正的**）
3. **失效** —— 你记着但现在已经不成立的（项目结束了、状态变了、工具换了）
4. **重新出现** —— 之前提过、最近又变得相关的旧事
5. **产出物变动** —— 那之后你为我**创建**或**改动**过、并且落在会话之外的东西（文档、指南、脚本、配置）。创建的写清楚存到了哪里（平台 + 库 / 目录 / 文件名）；改动的写清楚改的是哪一份、补了哪部分。只在会话里回答过、没落地成文件的不算

每一条都要求：

- 标 `[记]`（跨会话存着的）或 `[推]`（这次对话现推的）。不确定标 `[推]`
- **涉及我给你的指令、我的偏好、我对你的纠正时，一字不差引用我当时的原话**，别转述、别润色
- **写清楚这条信息是什么时候的**：我什么时候说的、事情什么时候发生的。只知道大概就写大概（"上周""这个月初"）。**完全不知道就写 `[无时间]`，不要猜**
- 涉及具体实体的用实体名起头（项目、人、工具、公司）

要求：

- 不要美化。负面的、尴尬的、自相矛盾的照原样写
- 不要合并同类项、不要概括
- 整份导出放进**一个代码块**里
- **列完直接停。不要写总结、不要写感想、不要在结尾加一段升华。**
- 代码块之后单独回答一句：这是全部变化，还是还有更多没列出来？
