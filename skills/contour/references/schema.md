# 实例文件的结构与写作规范

空白骨架在 `assets/templates/`，实例仓的完整结构和写入者划分在 `protocol.md`。本文件讲的是跨文件通用的写法约定——它们看着琐碎，但都是为了让档案在一年后还能用。

---

## 通用约定

### 时效标记

事实型条目后缀写明何时为真：`小学三年级（2025-07 时点）`。

不写时效的条目会在一年后以满分自信撒谎，而且没有任何迹象让下游察觉。**这是这类档案最常见的死法。**不知道确切时间就写模糊的（`2025 年初`），比留空强。

### 待确认

来自冲突消解、尚未得到用户答复的条目，写成：

```
[待确认] 主力 AI 工具  ← Codex 记为 A，Claude Code 记为 B，两边都没有条目级时间依据
```

标记要带**冲突的双方和来源**，不能只写"待确认"。下次问用户的时候，你需要的正是这些。

明细进 `review/`，`profile.md` / `now.md` 正文里只留标记——**别让待确认把正文撑成一锅粥**。

### 取代与撤回

```
superseded by E-041 · 2026-08-11        # 正常演化，旧条目留着
[已撤回 2026-08-11] · 主题：<粗粒度>     # 用户要求移除，原文不保留
```

两者语义不同：取代是"这条过时了"，撤回是"这条不该在这儿"。**不要用取代来实现撤回**——取代会把原文留在文件里。

### 证据编号

`evidence.md` 用 `E-001` 起递增，**编号永不复用**（归档压缩后也不回收）。结论侧用 `← E-023, E-041` 回指。

### 断言句，不是建议句

写「不要用鼓励式话术开场」，不写「他可能不太喜欢被鼓励」。

档案是给模型执行的，不是给模型参考的。软化过的表述会被当成可选建议忽略掉，尤其在模型有其他倾向的时候。

### 别写礼貌话

不要在文件里写「请注意」「希望这能帮到你」这类给 AI 看的客套。它占上下文、稀释指令密度，而且会诱导模型用同样的腔调回话。

### 语言

跟用户日常使用的语言走。档案会被多个端消费，混合语种会让部分端的召回变差。

## 各文件要点

### `profile.md` —— 慢变人格层

四节：**价值排序 / 判断路径 / 能力画像 / 负向约束**。

价值排序要写成有序的，不是并列的形容词堆。「稳定性 > 收益」比「重视稳定，也追求收益」有用得多——冲突的时候前者能判，后者不能。

判断路径写他**怎么**做决定，不是他决定了什么。

能力画像要带证据强度：亲眼见过成品的，和他自己提过一句的，不是一回事。

负向约束单列一节，别混在别的节里。原生记忆系统几乎不记否定，这一节是知界独有的补充，混进去会被稀释掉。

每条结论带 `← E-xxx`。追不到出处的不进这个文件。

### `now.md` —— 快变用户状态

**文件头第一行强制写"最后更新：YYYY-MM-DD"。** 它是这份文件唯一的可信度指标。

**降权阈值按它自己声明的变化速度推，不要写死一个月。** `now.md` 是周级变化的，所以超过两个变化周期没更新就该降权；用户如果把某一节标成日级（比如求职进度），那一节的阈值就更短。**从字段的预期变化频率推阈值，别记一个通用数字。**

内容：活跃项目、当前目标进度、健康与精力、家庭动态。**只装用户状态**——基础设施状态（锚点在哪、各端游标、探测结果）不在这里，见下面 `config.md` 和 `state/`。

条目可以删。这是唯一允许日常删条目的文件——过期状态转写进 `evidence.md` 留档后，正文里删掉。留着旧状态混在新状态里，比没有更危险。

### `sources.md` —— 两个分区

**不保存完整内容**，只保存指针。它回答"去哪拿答案"，不回答"答案是什么"。**最后验证时间是这份文件自己的保质期**——指针也会烂：项目挪了目录、数据库改了名、connector 掉了授权。

写法见 `consolidate.md` 第五节。两个区的结构不同：

**动态信源路由**（去哪拿最新事实）用表格，按信息领域组织，每条至少：识别线索、首选权威来源、需要时的深入来源、**来源不可用时怎么办**、最后验证时间。

**知识资产路由**（已经沉淀过什么）用记录块，编号 `A-001` 起递增、**永不复用**（跟 `E-xxx` 同规矩）。必填七键，一个都不许省：

```text
### A-003 · <主题>
- **调用线索**：主题词、同义说法、场景、用户对它的模糊指称
- **权威资产**：<系统 + 位置 + 标题>
- **覆盖范围**：正面覆盖什么，**以及不含什么**
- **超出覆盖时**：下一跳去哪
- **来源不可用时**：读不到时怎么说、提示检查什么
- **来源记录**：<端> <创建/更新> <日期> · <dump_id>（可多条）
- **最后验证**：YYYY-MM-DD
```

可选键两个：`特殊说明`（这份资产独有的使用限制才写，通用行为不要逐条重复）、`状态`（`待复核 · <日期> 收到更新报告`、`superseded by A-007 · <日期>` 或 `[已撤回 <日期>] · 主题：<粗粒度>`）。

**修改报告不等于验证。** 只能看到某端“我改过”的倾倒时，追加来源记录并标 `待复核`，不要改覆盖范围，也不要刷新最后验证；实际重新读取资产后才更新这两项并移除待复核状态。

**块结构的漏填是隐形的**——表格里空单元格看得见，块里少一行看不见。所以必填键缺信息时写 `未知` / `未验证`，**不许整行省掉**。这跟 `state/endpoints/` 那条"没跑过的写未测，不留空"是同一条纪律，理由也一样：空白会被下一轮当成填过了。

**`超出覆盖时` 和 `来源不可用时` 不是同一件事，不要合并。** 前者是资产读得到但不含这块，走下一跳；后者是资产打不开，那是**故障**，没有下一跳，要提示用户检查路由。合并了，路由烂掉就永远不会被发现。

### `config.md` —— 稳定实例配置

锚点位置、纳入端清单、权限边界、发布路径（条件直写 / 分支 PR / 自动化串行）、初始化状态、当前统一版本。

每个纳入端都要记录 baseline 的 `dump_id`，不能只写一个无法追责的“已完成”。初始化状态只允许三种语义：

- **等待第二端基线**：还没有两个不同的已登记端提交有效 baseline；不得生成统一文件或消费包
- **暂定版本**：至少两个不同端完成 baseline，已经发布第一版，但仍有已登记端待完成
- **冷启动完成**：所有已登记端都完成 baseline

第一版统一资产尚未发布时，当前统一版本明确写“尚未发布”，不要用 `v0` 假装已经有可加载的统一结果。两端门槛不区分网页端或本地端；空内容但格式合规的 baseline 也算。

**变化很慢，而且每次变都该被记住**——配置变更要留时间和原因。

**这里不放各端游标。** 游标频繁变化且每端各写各的，塞进共享文件就制造了并发热点。

### `state/endpoints/<endpoint-id>.md` —— 每端状态

**只由该端自己写**，所以端与端之间无冲突。装法、最后一次倾倒、最后读到的统一版本、各项探测结论、能力清单、验证结果。

**但同一个端可能同时开着两个会话**，写的是同一份文件，后写的会盖掉先写的游标。所以这份文件的写回也要走条件写入——只是冲突代价低，重取当前状态、重填自己这一轮的字段即可。

**没跑过的项写"未测"，不留空。** 空白会被下一轮当成"测过且正常"。

`endpoint-id` 描述产品表面，不含模型名——换模型不是换端，模型名放每次倾倒的元数据里。

### `evidence.md` —— 证据仓

**日常只追加，不改不删。** 正常演化用取代关系表达：旧条目留着，标 `superseded by <编号> · <日期>`。

**但用户明确要求撤回时必须能撤。** 撤回的条目替换成不含敏感原文的墓碑：`E-023 · [已撤回 <日期>] · 主题：<粗粒度主题>`，并在 `review/` 留记录供下次整合拦截。

**撤回只处理 `evidence.md`，原文仍在倾倒包里可读**——要连原文一起清得走脱敏，那是一个单独确认、走完整发布流程的动作。保证边界和代价见 `consolidate.md` 第七节。

按"支持哪条结论"组织，不按时间流水。每条：编号 · 日期 · 来源 · 内容 · `→ 支持：...`。

来源要具体到端和场景（`Claude Code 会话史 2025-07`、`ChatGPT 基线倾倒 2026-08-09`），因为冲突消解和体检都要用它追责。

体积会涨。定期把已被充分吸收的条目压缩归档，正文留摘要和编号——**编号不回收，链接才不会断**。

### `routing.md` —— 唯一常驻的那份

两张表：沟通路由（场景线索→策略→为什么）、记忆关注策略（信号→归哪层→为什么值得留）。写法见 `consolidate.md` 第四节。

**不承载信息源路由**，那是 `sources.md` 的活。这两件事混在一张表里，"怎么说话"和"去哪查"会互相稀释。

这份文件要控制长度，因为它常驻。判据：如果它长到让用户觉得每次对话都被它拖慢，就该精简了——留高频真实场景，把长尾挪进 `profile.md` 让模型按需读。

### `tests.md` —— 判断题与体检记录

两部分：题库、历次体检记录。出题与记录格式见 `audit.md`。

题目要标明对应 `routing.md` 的哪一条，这样不合格时能直接定位到要改哪行。

**这份文件不进被测身份的上下文，也不随公开技能分发。** 隔离的是身份不是端——同一产品可以在一个会话当主考、另一个会话当被测。
