# 加载 · 指令与记忆

将沟通与记忆策略接入当前端的指令上下文，并向该端提供统一档案中的相关内容。分别记录指令更新、材料送达、当前会话读取和原生记忆状态。

## 选择加载方式

分别根据当前端的档案访问能力和记忆机制选择加载方式。优先使用已有配置；缺少完成本轮操作所必需的信息时，再查询或向用户确认。

需要区分：

- **档案访问**：当前端能否通过可用的文件、MCP 或其他接口读取档案，读取的是权威内容还是带版本的副本。
- **记忆使用**：该端能否直接修改授权的记忆文件、调用记忆接口，或只能在当前会话中读取材料。

平台测试过程、日期和环境属于开发验证记录。运行时依据当前配置和操作结果，不因产品名称推断它的文件或记忆能力。

下文的文件导入、受管区块、项目文件和只读投影是常见示例，不是穷尽列表。插件、MCP、附件或其他当前可用的接口同样可以使用；是否完成加载以目标端实际读到的内容为准。

## 加载哪些内容

| 内容 | 加载时机 |
|---|---|
| `routing.md` | 放入当前端可用的常驻指令位置，保持简短 |
| `profile.md` | 需要稳定背景时读取 |
| `now.md` | 涉及近期状态时读取，并检查时间 |
| `sources.md` | 需要查证当前事实或定位已保存资料时读取 |
| `evidence.md` | 需要核对来源或处理冲突时读取 |
| `config.md`、`state/` | 配置和同步时使用，不作为用户画像送回 |
| `tests.md` | 仅由主考身份用于评估，不进入被测身份上下文 |

在指令位置同时提供档案入口及以下操作提示：

```text
涉及当前或最新事实时，按 sources.md 查询相应来源；无法查证时说明依据的日期和范围。
需要更新档案时使用知界同步流程。
```

技能按任务加载，不等于其内容在每次对话中都已出现。选择指令加载方式时，区分文件已保存、当前会话已读取和后续会话可用。

## 装法一：文件导入

适用于当前端已支持并配置了指令文件导入的情况。以下是支持 `@路径` 导入时的示例，不适用于仅将路径当作普通文本的端：

```markdown
## 个人档案（知界）

@<档案本地路径>/routing.md

档案位置：<路径>
需要稳定背景读 profile.md；涉及近期状态读 now.md；查证来源读 sources.md；
需要依据读 evidence.md。按当前任务读取相关部分。
要更新档案时使用知界同步流程。
```

导入方式和副本新鲜度分别核对。使用副本时，按当前执行端实际可用的路径获取最新已发布版本，并记录当前使用的版本；配置中的接入记录用于定位和复用，不把本端锁死在旧路径。Google Drive 档案按 `google-drive.md` 先判断原生 Google Docs 路径或 Adapter。

## 装法一之二：受管区块

适用于指令位置能保存文本、但不能自动导入外部文件的情况。将 `routing.md` 内容及读取入口写入用户授权位置的受管区块，保留该位置的其他内容。

```markdown
<!-- contour:begin · 来源：<档案位置> · 版本：<版本> · 生成于：<日期> -->

（routing.md 内容与档案读取入口）

<!-- contour:end -->
```

受管区块是副本。每次相关内容更新后重新生成；倾倒时标明其知界来源，不计作独立原生记忆。

## 装法二：项目文件

适用于目标端支持项目文件或附件，并能在所需上下文中读取它们的情况。上传 `routing.md` 并在指令位置记录文件入口、版本和日期。

```text
知界路由：<文件位置>，版本 <版本>，生成于 <日期>。
使用前读取；无法读取时说明本轮未加载。
涉及当前事实时按 sources.md 查询相应来源。
需要更新档案时使用知界同步流程。
```

以目标端实际读到的内容作为回执：上传成功只说明已送达；让目标端读取并报告条目标识或版本后，才记为当前会话已读取。后续会话能否自动使用另行记录，不因上传成功标为常驻；需要常驻而当前方式做不到时，改用其他可用方式，例如受管区块或只读投影。只有加载机制不明、确实妨碍本轮结果时，才按 `probe.md` 的 P-2 做专项诊断。

## 装法三：只读投影

适用于目标端能保存自定义指令文本，但无法直接读取档案的情况。仅投影简短的 `routing.md`，不复制完整数据层。

```text
以下内容由知界从 <档案位置> 生成，版本 <版本>，日期 <日期>。
通过知界同步修改；倾倒时将本段识别为知界提供的内容。
```

记录投影版本。内容更新后通过当前可用的通道刷新；需要用户上传或粘贴时，提供准备好的材料并记录待送达，完成后再更新状态。

## 副本更新

受管区块、项目文件和只读投影都要保留来源、版本或生成时间。判断副本是否需要更新时使用这些元数据，不依赖旧文件已成功加载。

按档案实际变化安排刷新。无法更新时保留待办并说明当前使用的版本，不报告已经生效。

具体上传或更新操作由当前连接提供。不要从某次历史测试推断所有端都需要人工上传，或所有端都能自动完成。

## 喂 · 提供统一记忆

在保护本端尚未倾倒的信息后，提供本轮相关统一结果：

- 稳定画像及有明确时间的近期状态。
- 快变信息的查询入口。
- 已有知识资产的主题、位置与覆盖范围。
- 对旧信息的更正、取代和撤回说明。

`routing.md` 按上文接入指令位置；原始依据按需读取。隐藏题库不随材料送回。

### 知识资产的最小卡片

提供主题、权威位置和正面覆盖范围。详细限制、来源记录及超出范围后的处理保留在 `sources.md`，需要引用资产时读取。

记忆中的卡片用于帮助定位资料，不能代替读取原文及适用范围。召回效果按 `probe.md` 的 P-4 观察。

### 可直接写入记忆文件的端

使用用户授权的全局记忆位置或既有记忆系统，保留其结构和其他内容。项目级 `CLAUDE.md`、`AGENTS.md` 不作为个人档案的默认写入目标。

写入后回读核对实际内容。文件已保存与后续会话已加载分别记录，不因写入成功就断言模型行为已改变。

### 通过平台记忆接口接收的端

按目标端已有的记忆接口或材料加载方式提供内容，明确需要更正或撤回的旧信息。平台是否保留以及如何压缩，以可观察结果为准。

当前会话复述只能证明该会话能访问材料。评估跨会话可用性时，使用开启原生记忆的新普通会话，并排除重新提供同一材料的影响；无法观察后台存储时保留该限制。

### 形态翻译：需要时调整表达

优先使用清晰的事实、策略、适用条件和理由。如果已有证据表明该端压缩后丢失否决条件或判断理由，可调整表达并重新观察：

- 按该端支持的类别组织内容，保持原意。
- 将需要执行的沟通偏好写成明确动作，保留适用条件。
- 将必要理由与策略一起表述，减少两者失去关联的风险。
- 较长材料按主题分批提供。

这些写法不能保证平台一定保存或完整召回。是否需要改写以及改写后的效果，见 `probe.md` 的 P-1；不要预设所有记忆机制都有相同损耗。

## 执行与结果记录

1. 读取当前端已有配置，选择可用的指令和记忆加载方式。
2. 更新授权的指令位置或准备待送达材料。
3. 让目标端读取本轮相关内容，并检查实际操作结果。
4. 在本端状态中分别记录指令更新、材料送达、会话读取、原生记忆状态、依据和未完成事项。

需要独立行为评估时使用 `audit.md`：主考读取题库，被测身份仅接收题面。通道检查只能证明资料可达，不能代替行为评估。

在统一内容更新、新端接入或实际出现加载异常时处理相关加载。模型或平台变化后，先检查已有配置是否仍适用，再针对受影响部分复核；不重复已经足够且仍适用的验证。
