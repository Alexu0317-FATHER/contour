# 加载 · 装 + 喂

整合完不装不喂，等于没做。这一步有两件事，缺一件闭环就不成立：

- **装**：把 `routing.md` 接进这一端的常驻上下文，让它每轮都在
- **喂**：把整合结论送进这一端自己的记忆系统，让那一端的记忆本身变对

只装不喂，档案再漂亮，各端该怎么错还怎么错——**"各端表现趋同"这个承诺是在喂这一步兑现的**。

---

## 两条分界线，它们不重合

各端的差异不是一维的。做加载之前先把这两个问题分开问：

| | **加载层分界** | **记忆层分界** |
|---|---|---|
| 问题 | 这一端能不能读到信源文件？ | 这一端的记忆是文件，还是平台黑盒？ |
| 决定什么 | 数据层能不能按需读 | "喂"这个动作怎么做、结果确不确定 |
| 是 | Claude Code、Codex，以及配了 MCP / connector 的线上端 | Claude Code、Codex（记忆就是 `CLAUDE.md`/`AGENTS.md`/自建记忆目录） |
| 否 | 裸网页端 | ChatGPT、Claude.ai（记忆是不可审计的黑盒） |

一个端可能在两条线上落在不同边。**Claude Desktop 就是个陷阱**：它是桌面应用，但登的是 claude.ai 账号，记忆很可能跟网页端是同一份黑盒。**按"本地/线上"想当然会判错，实测。**

---

## 装什么、不装什么

**常驻的是 `routing.md` 全文，加一小段包装。** 其余按需读——全塞进常驻上下文会挤掉用户真正要干的活，而且档案越完整挤得越狠，做得越好越难用，这是个会自己咬自己的设计。

### 那一小段包装，三行，一行都不能省

```
问到「当前 / 最近 / 最新进度 / 下一步」这类快变信息时，先按 sources.md 查权威来源；
查不到就说明答案基于哪次同步，不要拿旧记忆冒充最新。
档案由知界维护，不要直接改档案文件。要同步说「同步知界」。
```

**只装 `routing.md` 是不够的**，这三件事必须每轮都在：

| 这一行 | 不写会怎样 |
|---|---|
| 快变信息去 `sources.md` 查 | 模型不知道有这么个东西，会拿 `now.md` 的旧摘要当最新状态，**语气还特别笃定**。档案做得越好、传得越广，这个错就越可信 |
| 查不到时说明依据哪次同步 | 失败时静默降级成"凭记忆答"，用户看不出区别 |
| 同步入口 | 用户不知道该说哪句话，那个"最多问一次"的提醒又是概率性的，两头都漏就等于没有入口 |

注意这是**指针不是内容**：`sources.md` 全文不常驻，常驻的只是"遇到快变问题要去查"这条反射。

| | 什么时候进上下文 | 为什么 |
|---|---|---|
| `routing.md` | 常驻 | 「该怎么说话」必须每次都在，事后再读就晚了 |
| `profile.md` | 需要深背景时读 | 慢变，一次读足够管很久 |
| `now.md` | 涉及当前进度时读 | 快变，读了就得是新的 |
| `evidence.md` | 需要出处、或要做跨场景调用时读 | 体积最大，且大部分时候用不上 |
| `tests.md` | 只在体检时读 | 它是测试基础设施，不是给日常对话用的 |

### 先看清楚：装技能 ≠ 常驻

网页端现在都能上传技能包。**但装上技能解决不了加载问题**，因为技能是渐进式披露的：

| 级别 | 什么时候在上下文里 |
|---|---|
| `name` + `description` | 一直在 |
| SKILL.md 正文 | 只有 description 匹配上当前任务时 |
| `references/` `assets/` | 更晚，正文指示去读才加载 |

这是技能的设计核心，不是某个端的限制。而 `routing.md` 要的是**每次都在**——等某个任务匹配上才加载，前面几轮已经用错语气说完了。

**装技能真正解决的是另一件事**：那一端从此能自己跑倾倒、整合、加载、体检的完整流程，不必事事回本地端。这很有用，但它属于"流程可用性"，不是"档案常驻"。两件事都要做。

## 装法一：`@路径` 导入 —— 只有 Claude Code 验证过

Claude Code 的 `CLAUDE.md` 支持 `@路径` 导入，由 harness 确定性展开，全文进上下文。这是最优解——但它给的保证要说准：

> **`@路径` 保证"确定性读到本地那一份"，不保证"本地那一份是最新的"。**

实例仓在 GitHub 上，本地那份就是 **clone，clone 就是副本**，只有在有人 `git pull` 过之后才是最新的。追平必须发生在模型看到文件**之前**，而 MVP 不默认开会话启动钩子（见 `drive.md`），**所以本地端的新鲜度取决于上一次同步什么时候跑的**——这不是缺陷，是 MVP 有意接受的延迟，但要在 `state/endpoints/` 里如实记着上次追平的版本。

**Claude Desktop 是否支持，待测**（它是桌面应用但登的是 claude.ai 账号，别按"本地"想当然）。

```markdown
## 个人档案（知界）

@<实例仓本地路径>/routing.md

实例仓：<路径>
需要深背景读 `profile.md`，涉及当前进度读 `now.md`，需要出处读 `evidence.md`。
不要一次全读。

问到「当前 / 最近 / 最新进度 / 下一步」这类快变信息时，先按 `sources.md` 查权威来源；
查不到就说明答案基于哪次同步，不要拿旧记忆冒充最新。

档案由知界维护。你在对话中发现了值得留的新信息，按上面的记忆关注策略处理，
不要直接改档案文件。要同步说「同步知界」。
```

最后那句要写。没有它，各端会各自动手编辑档案，几轮下来就是并发写冲突。

**注意 `routing.md` 用的是导入不是指针，其余才是指针。** 写一句"会话开始时读 `routing.md`"就把确定性降回了概率性——用户第一句是"修这个 bug"，模型直奔 bug，那次读取不会发生。

## 装法一之二：受管区块（Codex）

**Codex 不展开 `@路径`。** 这是实测结论，不是推断：

> 在根 `AGENTS.md` 里只写 `@.codex-atpath-probe.md`，目标文件存一个随机标记，启动禁用文件工具的无上下文 sub-agent —— 返回 `NO_TOKEN`。
> 对照组：把另一个随机标记直接写进 `AGENTS.md`，同样的 sub-agent —— 准确返回。
>
> 结论：Codex 会加载 `AGENTS.md`，但**不会把其中的 `@路径` 自动展开成目标文件全文**。路径仍可作普通指针由模型主动调用文件工具读取，但那是概率性的，给不了"模型开始回答前 routing 全文已在上下文"的保证。

所以 Codex 端把 `routing.md` 的**内容**写进 `AGENTS.md` 的受管区块：

```markdown
<!-- contour:begin · 由知界从 <实例仓> 生成于 <日期> · 手改无效，请改实例仓 -->

（routing.md 全文）

<!-- contour:end -->
```

其余文件仍留路径指针，按需读取。

**受管区块是副本，所以它会过期**——纪律跟装法三（只读投影）完全一样：带生成日期、每次同步重新生成、倾倒时跳过。不要因为它写在本地文件里就当成活导入。

---

## 落点选择的连带影响

用户全是本地端的话，实例仓放本地目录能白拿一个"永远最新"。但 MVP 的端范围里有 claude.ai 和 ChatGPT，**它们逼着实例仓必须上远端**——于是本地端也跟着付出追平成本，Codex 还要额外付一次受管区块的重新生成。

这是范围决定的，不是可以优化掉的。别把"本地端零维护"算进预算。

## 装法二：项目文件（记忆是黑盒但能挂文件的端）

ChatGPT 的文件库、Claude.ai 的 Project Files。把 `routing.md` 传上去，**指令位只写一行指针，不粘内容**：

```
个人档案：routing.md（在项目文件 / 文件库「知界」目录下），生成于 YYYY-MM-DD。
会话开始先读它。读不到就直接告诉我读不到，别接着往下聊。
今天距生成日超过 <阈值> 天，先提醒我更新。

问到「当前 / 最近 / 最新进度 / 下一步」这类快变信息时，先按 sources.md 查权威来源，
查不到就说明答案基于哪次同步，不要拿旧记忆冒充最新。
要同步说「同步知界」。
```

这样指令位保持极短，`routing.md` 长到多大都不挤上下文。

**装完当场测一件事**：项目文件是确定性进上下文，还是按相关性检索召回？如果是检索，用户第一句问了个跟档案无关的事，它就不在——那又回到了我们要避免的失败模式，而且失败得更隐蔽，因为文件明明摆在那儿。

测法与三种结果各自怎么办，见 `references/probe.md` 的 P-2。**测出是检索就别硬撑装法二**，降级到装法三。

### 那三行日期检查为什么在指令位，不在文件里

**过期检测不能依赖被检查的对象加载成功。** 把日期写在 `routing.md` 里，文件没加载时这个检查静默不执行——而"文件根本没加载"比"文件过期"严重得多。放在指令位，它同时抓两种故障：**过期**，和**加载失败**。

阈值按各份文件自己的变化速度设，别一刀切。`routing.md` 月级变化，天天报警等于训练用户无视报警。

## 装法三：只读投影（兜底）

项目文件也用不了时，把 `routing.md` 全文粘进自定义指令，头部加：

```
以下内容由知界从信源 <位置> 生成于 <日期>，只读。要修改请改信源，改这里无效。
倾倒时跳过本段——它是知界写的，不是这一端记得的。
```

这两行有三个职责，都要保留：**防止用户在框里直接改**（出现第二个写入点，然后静默分岔，事后无法归因）、**标明它多旧**、**倾倒时跳过**（否则知界自己写的东西会被当成"这一端记得的"收回去）。

代价讲明：实例仓更新后要手动重粘；**只投影 `routing.md`，绝不投影数据层**（行为指引过期几周影响不大，事实过期几周就开始撒谎）。

---

## 三种装法的共同纪律

装法一之外的三种（受管区块、项目文件、只读投影）**都是副本**，所以共用同一套纪律：

| | 生成日期头 | 每次同步重新生成 | 倾倒时跳过 | 过期检查放哪 |
|---|---|---|---|---|
| 受管区块（Codex） | ✅ | ✅ | ✅ | 区块头 + `AGENTS.md` 其余部分 |
| 项目文件 | ✅ | ✅ | ✅ | **指令位**，不在文件里 |
| 只读投影 | ✅ | ✅ | ✅ | 投影头部 |

**过期检查不能依赖被检查的对象加载成功**——所以项目文件那档要把检查放进指令位，它同时抓"过期"和"根本没加载"两种故障，而后者严重得多。

## 线上端的更新：没有官方自动化通路

**以下是 2026-08 的实测结论。平台会变，与你实际看到的行为不符时以实测为准。**

- **Claude.ai Project Files 没有官方 API。** Anthropic 的 Files API 属于 Platform API，跟 claude.ai 消费端是两个互相看不见的存储。
- **ChatGPT 文件库同样没有官方 API。** Google Drive 的 synced connector 确实存在（预先索引），但**只给 Pro / Business / Enterprise，Plus 不在内**；Plus 只能把 Drive 文件链进 Project，行为是"提示时才读，不监控文件夹、不响应触发"。
- **ChatGPT 的 Scheduled Tasks 指望不上**：任务里跑的是纯文本 prompt，不能上传文件、不能调 agent，定位是提醒而非执行。
- **第三方同步工具不要推荐给用户。** 这类工具靠 session cookie 工作，cookie 过期即静默失效——正是"写了但没读"那类最难发现的故障；它们的说明里通常也写明可能违反服务条款。更根本的是，它把一个必然存在的人工步骤伪装成自动化，**伪装比缺失更贵**。用户自己权衡后使用是他的自由，技能不替陌生用户做这个决定。

**所以线上端的常驻层更新，最后一步是人的动作**：知界在同步时生成一份带日期头的 `routing.md` 并告诉用户"该传了"，用户把它拖上去。这一步没有官方通路可以绕开。

注意区分两件事：**这里说的人工是"更新常驻层"，不是"搬运倾倒内容"。** 倾倒和读取统一结果走 connector，是自动的；只有把 `routing.md` 传进项目文件这一下要人动手。前者是日常同步的主体，后者是低频动作（`routing.md` 月级变化）。

而这正是那几行日期检查从"顺手加的保险"升格成承重墙的原因——**要人动手的步骤注定会漏，那一行是唯一能让它不静默腐烂的东西。**

连带结论：既然这点成本落在人身上，**常驻层必须小**。只传 `routing.md`，数据层靠各端自己的 connector 按需读——数据层晚一天刷新不致命，行为层晚一天就开始用错语气。

## 喂 · 把结论送进各端自己的记忆

装解决"每轮都在"，喂解决"这一端本身记对了没有"。**这一步才是各端表现趋同真正发生的地方。**

### 喂什么、不喂什么

| 文件 | 喂不喂 | 为什么 |
|---|---|---|
| `profile.md` | **喂** | 慢变结论，正是各端该对齐的东西 |
| `now.md` | **喂，但每条必须带时间** | 过期状态喂进去比不喂更坏——"他在找工作"，他上个月入职了 |
| `sources.md` 动态区 | **喂识别线索，不喂完整表** | 要让模型形成"问到最新状态就该去查"的反射；具体去哪查按需读 |
| `sources.md` 资产区 | **喂最小卡片**（见下） | 这一区的载荷就是"存在和位置"本身——原生记忆记住"他有一份 X 在 Y"，不用查表也能自己提起来 |
| `routing.md` | **不喂，走装** | 它要每轮确定性在场，交给概率性载体就废了 |
| `evidence.md` | 不喂 | 体积太大，而且它是原料不是结论 |
| `config.md` / `state/` | 不喂 | 基础设施状态，模型不需要 |
| `tests.md` | **绝对不喂** | 喂了等于把答案给考生，体检从此测背诵不测判断，整套验证机制当场作废 |

最后一行是硬规则，不是建议。

### 资产区的最小卡片：喂主题 + 位置 + 正面覆盖

**喂**：主题、权威资产在哪、覆盖范围的**正面那半句**。

**不喂**：`覆盖范围` 里"不含 X"那半句，以及 `超出覆盖时` / `来源不可用时` / `来源记录` / `最后验证`。

不喂否定边界的理由，是本文件末尾那个已经实测记录在案的失败长相——**禁令会被磨成偏好**。"不含 CI 和 submodule"是禁令形状的，进黑盒记忆会被压掉，而**磨掉之后剩下的是一个膨胀的覆盖声明**：模型记得"他有份 Git 指南覆盖日常操作"，于是不打开就告诉他"你那份指南里讲过 submodule"。

正面部分被磨掉只是变模糊，否定部分被磨掉会变成假话。**两种损耗不对称，只喂不会变成假话的那半边。** 边界细节留在 `sources.md` 里按需读。

**这一区不额外买常驻预算。** 资产路由的目标是"有几率被想起来"，不是"每轮确定性在场"——那正是喂的形状。喂是整合完本来就要跑的一步，加这几张卡片是免费的；常驻是最贵的资源，而且网页端每轮判断还要多一次连接器调用。召回率够不够是可测的，按 `probe.md` 的 P-3 测，不够再回头谈要不要买那一行。

### 记忆是文件的端：不存在"喂"这个动作

Claude Code、Codex 的记忆就是文件——**你不用请求它保存，直接写就行，写完确定生效**。装和喂在这些端合流了，都是写文件，只是写到不同位置。

**但只写全局，不写项目级。** `~/.claude/CLAUDE.md`、用户自建的记忆目录可以写；某个项目的 `CLAUDE.md` / `AGENTS.md` 不要碰——那些文件可能进 git、可能有同事、有该项目自己的约定。

**用户已有的本地记忆系统一律按该端原生记忆对待**（比如自建的记忆目录 + 索引文件）。它既是倾倒源，也是写回目标。不要求用户改造它的结构，也不试图取代它——它挂在 harness 层、每次会话自动加载，这个地位知界拿不到也不该抢。

### 记忆是黑盒的端：送材料，请求覆盖，然后验证

**一、按目标端自己的分类桶组织。**

claude.ai 官方给的记忆导出 prompt 用的是这五类：`Instructions` / `Identity` / `Career` / `Projects` / `Preferences`。按它组织着送过去，它的归类器就不用猜。ChatGPT 侧有没有对应的官方 prompt 值得找一找，有的话同样能反推它的桶。

**二、把陈述句改写成祈使句。**

选择策略认的是"规则"和"事实"，不认"人格描述"。所以别送人格描述：

| 档案里的原样 | 送出去的形态 |
|---|---|
| 他讨厌被当小白解释基础概念 | `Never explain basics unless asked.` |
| 他用"消费者是谁"判断一件东西该不该进系统 | `When he asks whether something belongs in a system, ask first: is the consumer the model or the human?` |

这不是绕过平台规则，是用它自己承认的形状说话——官方 prompt 里 `Instructions` 那一类明写着收 `"never do Y"` 和 `corrections to your behavior`。

**三、理由焊在规则后面，别分成两条。**

改写保得住策略，保不住理由——而"为什么"是 `routing.md` 能泛化到清单外场景的全部来源。补救是把理由压成一个短从句挂在规则尾巴上：

> `Never open with encouragement — he reads it as stalling and distrusts everything that follows.`

关键在"焊"：理由现在是这条规则的一部分，要么跟它一起被存，要么一起被丢，**不会被单独吃掉**。分成两条送，必然出现"规则留下、理由蒸发"。

**四、显式要求覆盖旧条目，不能只交新的。**

原生记忆是追加式的，旧的错条目不会因为你喂了新的就消失。只加不删，几轮之后每端都攒着一堆并存的矛盾记忆，召回哪条看运气——**这个循环是发散的**。ChatGPT 和 Claude.ai 都支持指名忘掉某条，喂之前先点名要更正哪些。

**五、分批交，一批一个主题。** 一次倒一大段容易被压缩成一句概括。

**六、验证要开新会话，当场复述不算数。**

当场反问"你现在记住了关于我的什么"，得到的可能只是它还看得见刚才那段对话——**这只证明材料送达，不证明持久保存**。模型口头说"记住了"更不能当证据。

真验证是**隔一段时间开一个新的普通会话**（原生记忆开着，不要用匿名或隔离模式）再问。手法见 `probe.md`。

盯一个失败长相：

> `Never explain basics` → `Prefers concise explanations`

**禁令被磨成偏好。** 强度掉一个量级，触发条件没了，理由没了，而且读起来还挺像回事——这是最难发现的一种失败。看到它就说明形态翻译在这一端还不够，换写法或者认下这一端的损耗，并在体检记录里标出来。

### 这一节的前提要实测

第二、三点整套建立在"选择策略不认负面项和判断路径"这个前提上。**各端未必都这样**，而认不认直接决定这道工序要不要做。

按 `references/probe.md` 的 P-1 测：原样喂一条负面项，隔一段时间开新会话看它剩下什么。三种结果对应三种做法，其中一种是整道工序都不用做。

---

## 顺序

1. 判两条分界线：这一端能读到实例仓吗？它的记忆是文件还是黑盒？两个问题分开答
2. **装**：Claude Code 用 `@路径` 导入；Codex 用受管区块；线上端传项目文件 + 一行指针；都不行才用只读投影
3. **验证装**：**不能自己出题考自己**——那是先看答案再参加考试，会让 `tests.md` 从此测背诵不测判断（见 `audit.md` 的身份隔离）。

   正确做法：读题库的是**主考身份**，被测身份只收到题面。同一产品用不同 session 就能分开——当前会话当主考，开一个干净会话当被测，把题面发过去，主考对着合格判据判。

   实在开不出第二个会话时，退而求其次用**通道题**：问它"你现在能读到 `evidence.md` 吗，第一条编号是什么"。通道题没有需要保密的答案，自问自答不损害题库。**但它只能证明数据层可达，证明不了行为层生效**，要在记录里标明这次验证是降级的
4. **喂**：记忆是文件的端直接写全局文件；黑盒端按上面六步走
5. **验证喂**：**开新会话**再问，不是当场复述。盯"禁令被磨成偏好"
6. 记进 `state/endpoints/<endpoint-id>.md`：装法、装的时间、两次验证结果、`probe.md` 各项探测的结论（还没回收的写"未测"，别留空——空白会被下一轮当成"测过且正常"）

第 3 和第 5 步别省。指令位写进去了不等于生效——路径错了、内容太长被截了、平台有自己的注入顺序，都会让它静默失效。而失效是静默的：模型照常回话，只是不知道你是谁。**"写了但没读"的基础设施比没有更糟，因为你以为它在工作。**

**验证结果要如实记，包括失败的。** 报了成功但其实没成，比没记录还糟——前者你至少还会怀疑。

## 什么时候要重新加载

- 每次整合之后（信源变了，线上端的副本就旧了）
- 用户新增一个端
- 用户换了模型（不同模型对同一份路由表的服从度不一样，装完要重新验证）
- 体检发现某端偏差变大
