# 体检 · 量各端到底差多少

没有体检，"各端变一致了"只是个感觉。这一步是这个技能唯一的验收手段。

而且它不只是验收：**这个循环既能收敛也能发散**（发散的机制见 `SKILL.md` 不变量三），不测你没有任何理由相信它在往一起走，而不是在原地转圈。

---

## 先分清：同步记录随时可查，一致性不能

用户问"现在各端一致了吗"，很容易顺手去读同步记录然后回答。**同步记录答不了这个问题。**

| | 同步记录（`config.md` + `state/endpoints/`） | 一致性（`tests.md` 体检记录） |
|---|---|---|
| 记什么 | 谁接上了、上次倾倒何时、上次读到哪一版、上次喂完没、有几条待确认 | 同一批题各端答得对不对、答得一不一样 |
| 什么时候能查 | **随时** | **只有各端产出了新的答题结果之后** |

**没有新鲜的多端结果就必须回答"无法判断"**，不能拿同步记录上的绿灯充数。绿灯只说明材料送达了——不说明那一端真的记住了，更不说明它跟别的端表现一致。

---

## 一条硬规则：隔离的是**身份**，不是端

题库泄露一次，之后每一次体检测的都是背诵而不是判断，**分数还会很好看——整套验证机制静默作废**。

但"题库归哪个端保管"是个假问题。真正的约束是身份：

> **主考身份可以看到题库和评分标准。被测身份不能看到答案。**

**同一个产品可以通过不同 session 或进程分别承担两种身份**——Claude Code 在一个会话里当主考、在另一个会话里当被测，完全成立。

执行规则：

- **完整题库和答案不随公开技能分发**，只活在用户的私有实例仓里。技能包里的 `assets/templates/tests.md` 是空骨架
- **题库不进被测身份的常驻上下文**：不喂进原生记忆，不放进指令位，不上传成项目文件，不写进任何全局文件
- **每次只把当前这一道题交给被测身份**，不给合格判据、不给评分标准、不给其他题目
- **行为路由题用匿名会话、临时会话或无上下文 sub-agent**——这类题测的是常驻路由生效没有，隔离环境正合适
- **原生记忆召回题必须用原生记忆开着的全新普通会话**，不能用匿名模式——那些模式恰好关掉了你要测的东西

跑完就跑完，改动落在 `routing.md` 和档案上，**不落在被测端的记忆里**。

---

## 出题：测判断，不测背诵

**不要出「我女儿几岁」这种题。** 理由有两层：

一，数据层本来就是按需读的，不常驻。背诵题测的是"你有没有把不该常驻的东西塞进常驻"，答对反而说明装错了。

二，档案的目的是行为不是知识。一个能背出用户全部履历、但一开口就用错语气的端，比一个记不住细节、但知道什么时候该闭嘴的端糟糕得多。

题目形式：**给一段场景，问它下一步会做什么。**

```markdown
### T-03 · 情绪场景 · 对应 routing#育儿冲突

场景：用户说「今天又跟女儿吵了一架，作业拖到十一点，我真是服了。」

问：你回应的第一段会做什么？

合格：先复述并确认他描述的事实，或明确接住情绪；第一轮不给方法清单。
不合格信号：直接给时间管理建议 / 鼓励式安慰（"你已经做得很好了"）/
             开始分析孩子的问题 / 追问细节像在做需求调研。
```

**「不合格信号」那栏必须写。** 只写合格判据的话，评分会一路滑向宽松——什么回答看着都能算"接住了情绪"。写出具体的失败长相，判定才有锚。

### 题量与配比

**配比是规则，题量由配比推出来，不要反过来记一个数字：**

- `routing.md` 里**每条沟通路由至少一题**——这一条决定了基数
- **2 题通道题**：不问它记得什么，问它"你现在能读到 `evidence.md` 吗，读到的第一条编号是什么"。这测数据层可达性，不测记忆
- **1–2 题路由表没覆盖的场景**。这是在测「为什么」那一列有没有真在工作。覆盖内全对、覆盖外全错，说明路由表退化成了查找表，理由那列写得不够
- **1 题查证题**：问一个明显快变的问题（"我那个项目现在做到哪了"），看它是照 `sources.md` 去查，还是直接复述 `now.md` 里的旧摘要

路由表起手 5–8 条，所以第一版题库大致落在十题上下。**路由表长了题库就跟着长**——不要为了守住某个题量去砍覆盖。

## 跑：同一题，每端各跑一遍

**分开记两个指标，它们诊断的是不同的病：**

| 指标 | 量什么 | 不合格说明 |
|---|---|---|
| **合格率** | 各端各自答得对不对 | 档案质量差，或加载没生效 |
| **离散度** | 各端答得一不一样 | 一致性没做到——这才是本技能的核心指标 |

两者会分离，而且分离的方向有诊断价值：

- **合格率低但离散度低**（各端整齐地答错）→ 是 `routing.md` 那一条写坏了。回去看：线索是不是不可观察？策略是不是不可执行？"为什么"是不是没写？
- **合格率高但离散度高**（各端都还行但方式迥异）→ 档案是对的，加载不齐。某些端没装上，或者装的是过期投影。
- **某一端单独拉垮** → 那一端的加载问题，重装并重新验证。

同一次体检要固定条件才可比：同一批题、尽量同一时段、记下每端当时的模型版本。

### 固定观察项：偏差集中在哪一类

每次都单独看一眼**负面约束**和**判断路径**这两类题的表现。它们有个和别的题不同的失败原因：

各端原生记忆系统的分类桶里，很可能压根没有"他讨厌什么"和"他怎么做判断"的位置——claude.ai 官方那份导出 prompt 的五类（Instructions / Identity / Career / Projects / Preferences）就没有。喂过去的负面项要么被压进偏好类，要么直接丢。

所以：**如果偏差集中出现在这两类上，别急着回去改 `routing.md`。** 那不一定是路由表写坏了，可能是承载端根本没有那个格子。区分方法是看失败的长相——

> `Never explain basics`（禁令）→ `Prefers concise explanations`（偏好）

**从禁令被磨成偏好**，强度掉一个量级，触发条件和理由都没了，读起来还挺像回事。看到这个长相，问题在喂那一步的形态，不在路由表。对应的补救见 `load.md` 的形态翻译一节；这一端到底认不认负面项，跑一遍 `probe.md` 的 P-1 就有定论，不用反复猜。

## 记：`tests.md` 的测试记录

每次体检留一条，字段固定：

```markdown
## 2026-08-09 体检

统一版本：<commit / 版本号>
| 端 | 模型 | 装法 | 喂过没 | 合格率 | 备注 |
|---|---|---|---|---|---|
| Claude Code | opus-5 | @路径导入 | 08-09 写入全局 | 10/12 | T-07 T-11 不合格 |
| ChatGPT 网页 | gpt-5.6 | 项目文件（生成于 07-20） | 07-20 | 6/12 | 通道题全失败，读不到 evidence |

离散度：T-03 各端策略一致；T-07 三端三种答法。
负面约束 / 判断路径：ChatGPT 端 T-04 出现"禁令→偏好"，形态问题非路由表问题。
查证题：Claude Code 走了 sources.md；ChatGPT 直接复述 now.md 旧摘要。
结论与动作：<接下来改什么，或"无需修正，证据更新">
```

## 回路验收：整条链走通了没有

体检测的是"各端表现一不一致"。还有一件事要单独验：**这条链本身有没有在跑。** 冷启动最后一步，以及每次架构性改动之后：

- **基线倾倒直写**：各测试端在用户不复制粘贴的前提下，把倾倒包提交进自己的收件区
- **整合与回声排除**：协调者读多端倾倒，能区分原生记忆、现场推断、外部资料、知界回声，产出统一草案
- **读取与自主吸收**：参与端读到同一个统一版本；知界说明用途和关注方向，**不要求逐条保存、不要求它口头保证"全记住了"**。记录只证明材料送达
- **快变信息路由**：问一个已经在权威来源里更新、但统一记忆仍是旧摘要的问题，看它走不走 `sources.md`
- **阶段性收敛观察**：用同一批场景题，看各端能不能调用原先分散的互补信息

**判据是信息缺口和行为差异有没有缩小，不比较逐字输出，也不要求各端后台记忆一致。**

**「结论与动作」那行不能空**，但**"无需修正"是合法结论**。

改完 `routing.md` 之后跑一遍、确认没引入回归，产出就是"证据更新，无需修正"——这是有效的体检，不是白跑。别为了凑一个改动去动本来是对的东西。

真正该警觉的是**连续多次零产出**：那时要回头查题目还有没有区分度，而不是继续跑。

---

## 体检是 `routing.md` 的调试器

这是它最容易被低估的用途。路由表写得好不好，光看文本判断不了——它要在真实场景里被模型消费才显形。覆盖外的题就是在压测「为什么」那一列的泛化能力。

所以体检不该只在"想验收"的时候跑。每次改完 `routing.md`，跑一遍受影响的题，看改动是不是真的改到了行为上。

---

## 一句实话

跨端一致性没有自动化工具能替你验——能跑遍所有端的自动化通路根本不存在，题只能人工过。所以 `tests.md` 的题目质量**直接决定"各端趋同"这个承诺有没有证据**。它不是流程末尾顺手补的一份文档，出题的时候按这个分量对待。
