# 探测 · 这一端到底能干什么

**目标是测"这个端此刻实际能调用和导出的记忆"，不是证明厂商后台存了什么。** 后者拿不到，别声称拿到了。

---

## 分层触发：别让测试吞掉初始化

不是每个新端一上来就把下面全跑一遍。按风险分四层：

| 层 | 什么时候跑 | 跑哪些 |
|---|---|---|
| **接入必测** | 每个端首次纳入，不可跳过 | 来源隔离（MV-04 / MV-05）、GitHub 通道（`protocol.md` 的 GH 系列）、一次完整同步、基础版本冲突能否正确拦截 |
| **能力探测** | 只测这一端**计划启用**的能力 | P-1 / P-2 / P-3 中相关的几项 |
| **行为体检** | 冷启动基线、路由改动后回归、怀疑偏差时 | 见 `audit.md` |
| **深度诊断** | 出问题时才跑 | MV-06 到 MV-10、回声与污染排查 |

不打算给某端配项目文件，就不用测 P-2。测试的意义是让决策有依据，不是刷覆盖率。

---

## 测试原则

- **用虚构的、无害的、可删除的测试事实。** 不拿真实家庭、健康、账号信息做探针——探针会留在各端记忆里，而你不一定清得干净
- **每条测试事实带一个独特且不可能自然出现的标记**，否则模型凭常识猜中你也分不出来
- **可见性测试开始前不加载知界文件**，否则会把统一画像误认成原生记忆
- **每项测试开新会话。** 涉及作用域时，分别在同一项目、其他项目、普通会话里各跑一次
- **原生记忆召回测试不能用匿名或隔离模式**——那些模式恰好关掉了你要测的东西。必须是原生记忆开着的全新普通会话
- **保存原文，不只记通过/失败**
- **测完清理**：删掉测试事实，并验证删除是否真的传播（MV-08）

### 测试事实准备

| 类型 | 测什么 | 形态 |
|---|---|---|
| 稳定偏好 | 跨会话持久召回 | 「我的测试饮品代号是 `<唯一标记>`」 |
| 项目限定事实 | 项目 vs 全局作用域 | 「在测试项目中，内部代号是 `<唯一标记>`」 |
| 明确否决及理由 | 负向记忆保不保得住 | 「不要使用 `<方案代号>`，因为 `<无害理由>`」 |
| 沟通纠正 | 程序性记忆 | 「遇到测试主题时，先复述事实，不要先给建议」 |
| 临时事实（负向对照） | 不该跨会话出现的 | 「这句话只供当前会话使用：`<唯一标记>`」 |

**测试事实是否真的被平台保存，要用该端自己的保存方式确认。** 确认不了就把记录标为"前置条件未知"——**别把"没保存成功"读成"记忆功能不行"。**

## 接入必测

### MV-04 · 知界回声隔离

**做什么**：先在干净会话跑一次自述倾倒；然后加载一份含独特标记的知界测试画像，再次要求倾倒，包的 `contour_context_loaded` 标 `true`。

**通过**：模型把那个标记归到"已加载的知界文件"，不是"原生长期记忆"。

**不通过**：记为**反馈回路高风险**——这一端的倾倒物需要整合时格外依赖差集来兜底。

### MV-05 · 项目文件与自定义指令隔离

**做什么**：在项目文件或项目指令里放一个独特标记，在该项目内和项目外分别倾倒。

**通过**：项目内看到时标为项目/工作区来源；项目外不声称它是全局记忆。

### GH 系列 + 一次完整同步

见 `protocol.md`。**能看见仓库不等于能写进去**，必须实际提交并回读。

还要验证一次基础版本冲突：故意用过期的基础版本发布，看它是被拦下重来，还是直接覆盖了。**拦不下就说明这一端的发布路径不安全，不能让它当协调者。**

## 能力探测

### P-1 · 负面项原样喂进去会怎样

**测什么**：这一端的记忆系统认不认「不要做 X」这种形态。`load.md` 里那套形态翻译工序，整个建立在"它不认"这个前提上。

**怎么测**：用**虚构的**否决事实（"不要使用 `<方案代号>`，因为 `<无害理由>`"），不做任何改写，原样喂进去。隔一段时间开新会话问它记住了什么。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 原样在，禁令强度没掉 | 它认负面项 | 跳过形态翻译，直接送原文，省一整道工序 |
| 变成了正面偏好（`Never explain basics` → `Prefers concise explanations`） | 选择策略在改写 | 按 `load.md` 的形态翻译整节做，把这一端标为高损耗 |
| 完全没有 | 分类桶里可能没有这个格子 | 形态翻译救不了。改走装——负面约束塞进常驻的 `routing.md`，并在体检记录里注明这一端的负向约束靠常驻而非记忆 |

**测完清掉那条虚构否决**，别让它长期影响这一端的行为。

### P-2 · 项目文件是确定性注入，还是检索召回

**测什么**：装法二成不成立。如果是检索召回，用户第一句问了跟档案无关的事，路由表就不在——正是要避免的失败模式，而且失败得更隐蔽，因为文件明明摆在那儿。

**怎么测**：往 `routing.md` 里埋一条只有它知道的行为判据（例：「回答任何问题前，先用一句话复述我的问题」）。开全新会话，第一句问一个**跟档案完全无关**的问题，看它走没走那条判据。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 走了 | 确定性注入 | 装法二成立 |
| 没走，但直接问「我的档案里写了什么」时读得到 | 检索召回 | **装法二不成立，别硬撑。** 降级到只读投影；项目文件退回去只承载数据层（`profile` / `evidence` 按需读，那本来就适合检索） |
| 连问都读不到 | 文件没挂上或被截断 | 先修加载，别急着下机制结论 |

**测完撤掉那条临时判据。** 它会改变这一端所有回答的方式，留着就是长期污染。

### P-3 · 记忆关注策略到底影响谁

**测什么**：`routing.md` 里那张记忆关注策略表有两个可能的消费者，效力完全不同：

- **平台的原生记忆系统**——如果保存动作由模型主动发起（调用记忆工具），常驻判据直接有效；如果是平台后台跑抽取器扫对话记录，常驻判据基本无效
- **常驻上下文里的模型自己**——这条**确定成立**：模型读到"用户纠正 AI 的说话方式值得记"，本轮真发生了这件事时，就更可能在收尾时提议同步（见 `drive.md`）

沟通路由不受这个影响，它作用于模型的当轮输出，链条是直的。

**怎么测（两问，别混）：**

**第一问，测模型层**——在记忆关注策略里放一条独特判据（例：「凡是用户提到『试音』这个词，那句话连上下文一起记住」）。装好后开新会话，自然地说一句含那个词的话。**看模型在本轮收尾时有没有提议同步。**

**第二问，测平台层**——同一个会话结束后，另开一个新会话，问它记不记得跟那个词有关的事。

**必须有控制组**：同时准备一条**没有**写进记忆关注策略的相似事实，用同样的方式提一次。两条都被记住，说明是平台本来就会记，跟路由表没关系。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 模型提议了，新会话也记住了，且控制组没被记住 | 两层都有效 | 记忆关注策略照常驻，值得投入 |
| 模型提议了，新会话没记住 | 只有模型层有效 | 保留常驻——它驱动的正是 `drive.md` 那一问，仍然有用 |
| 模型也没提议，新会话也没记住 | 都无效 | 把这张表撤出常驻，挪进 `profile.md` 按需读，常驻只留沟通路由。省下的预算是真金白银 |
| 控制组也被记住了 | **测试无效**，平台本来就记这类事 | 换一条更不起眼的测试事实重测 |

## 深度诊断

出问题时才跑。

**MV-01 · 干净会话直接枚举**：关闭知界加载，全新会话跑 `assets/prompts/self-report.md`。看它能否导出会话前就存在的测试事实，或坦白"不能枚举"。**不得把当前提示里的措辞推断成用户画像。**

**MV-02 · 被动召回 vs 主动枚举**：不问"你记得什么"，给一个确实需要那条测试偏好才能做对的小任务。任务里用对了但 MV-01 没列出 → 这一端"能召回但不能完整枚举"。**任务猜中不等于记忆可见**，两份结果分开记。

**MV-03 · 当前会话污染负向对照**：给一条临时事实并明确不要求保存，结束后新会话倾倒。临时标记不应出现。若出现，记录是平台真存了、会话泄漏还是模型猜的，**不能直接归类**。

**MV-06 · 作用域穿透**：同一问题分别在原项目、另一个项目、普通新会话里问。**不同范围表现不一致时，不许把它提升为全局记忆。**

**MV-07 · 更正传播**：保存一个事实，再用该端支持的方式明确更正，新会话倾倒。新事实被召回；旧事实要么消失、要么被明确标为旧版本，**不得两者并存当作当前事实**。

**MV-08 · 删除传播**：删除一条测试记忆后，新会话跑主动枚举和被动召回。仍出现就记录是删除延迟、作用域残留还是别的上下文来源。

**MV-09 · 负向约束与沟通偏好**：用包含测试主题的自然问题触发已保存的否决理由和沟通纠正。看它是只记住"不要做什么"，还是也保留了"为什么"和具体执行方式。

**MV-10 · 过期与矛盾识别**：准备有明确先后关系的旧状态和新状态，然后倾倒。能指出哪个是当前状态；无法判断时应同时列出并标冲突，**不得无声选一个**。

## 结果分级

| 结果 | 含义 |
|---|---|
| **无持久召回** | 新会话观察不到测试事实，或前置保存是否成功无法确认 |
| **可被动召回** | 相关任务中会用记忆，但主动倾倒列不稳 |
| **可自述倾倒** | 能列出可访问记忆并基本区分来源，但不代表后台存储被完整导出 |
| **可核对导出** | 自述结果能跟该端的设置页或正式导出交叉核对 |

**分级描述能力，不代表产品优劣。** 知界的倾倒协议必须能适应"只能被动召回"和"只能自述"的端，不能假定所有端都有正式导出接口。

## 记录

结果写进 `state/endpoints/<endpoint-id>.md`，模板在 `assets/templates/`。至少要有：

- 产品与表面、模型、账号或项目范围
- 原生记忆是否开启：是 / 否 / 无法确认
- 测试前是否加载知界：应为否
- 锚点连接方式与逐项能力（读 / 搜索 / 提交 / 更新 / PR / 合并）
- 各测试项的结果 + **原始证据位置**
- 可见性结论、作用域结论、污染与回声风险
- 下一步

**没跑过的项如实写"未测"，别留空。** 空白会被下一轮当成"测过且正常"。

## 什么时候重测

- 用户换了模型（同一平台的不同模型对同一份路由表的服从度不一样）
- 平台改版，尤其是记忆功能或项目文件功能有变动
- 体检发现某端偏差**集中在负面约束或判断路径这两类**上——那多半不是路由表写坏了，是这一端的承载能力变了，先回来重测 P-1
