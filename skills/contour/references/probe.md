# 探测 · 接入与记忆可用性

记录当前端在指定条件下能读取、提交、加载和召回的内容。结论限于观察范围，不将可见回答当作平台内部存储的完整证明。

---

## 按目的选择检查

正常接入和同步以本轮实际读取、提交、发布和回读的结果为准，不需要先跑本文件的检查。本文件用于开发验收或明确的诊断：选择相关项目，复用仍适用的已有记录。

| 层 | 什么时候跑 | 跑哪些 |
|---|---|---|
| **验收与发布诊断** | 开发验收、首次采用某条发布路径、怀疑来源混淆或覆盖时 | 来源隔离（MV-04 / MV-05）、通道验证、一次完整同步、过期基础版本的发布能否被拦截 |
| **能力探测** | 计划启用某项能力、且其机制不明会影响结果时 | P-1 / P-2 / P-3 / P-4 中相关的几项 |
| **行为体检** | 用户或开发者安排的一致性检查、路由改动后回归、怀疑偏差时 | 见 `audit.md` |
| **深度诊断** | 出问题时才跑 | MV-06 到 MV-10、回声与污染排查 |

仅检查与当前目的相关的能力，例如未使用项目文件时不运行 P-2。

## 测试原则

- **用虚构的、无害的、可删除的测试事实。** 不拿真实家庭、健康、账号信息做探针——探针会留在各端记忆里，而你不一定清得干净
- 使用随机且独特的测试标记，降低模型凭常识猜中的可能。
- **可见性测试开始前不加载知界文件**，否则会把统一画像误认成原生记忆
- **每项测试开新会话。** 涉及作用域时，分别在同一项目、其他项目、普通会话里各跑一次
- 原生记忆召回测试使用已开启该功能的新普通会话；隔离测试身份时保留被测功能，避免关闭记忆后把无召回当作失败。
- **保存原文，不只记通过/失败**
- **测完清理**：删掉测试事实，并验证删除是否真的传播（MV-08）

### 测试事实准备

| 类型 | 测什么 | 形态 |
|---|---|---|
| 稳定偏好 | 跨会话持久召回 | 「我的测试饮品代号是 `<唯一标记>`」 |
| 项目限定事实 | 项目 vs 全局作用域 | 「在测试项目中，内部代号是 `<唯一标记>`」 |
| 明确否决及理由 | 负向记忆保不保得住 | 「不要使用 `<方案代号>`，因为 `<无害理由>`」 |
| 沟通纠正 | 程序性记忆 | 「遇到测试主题时，先复述事实，不要先给建议」 |
| 临时事实（负向对照） | 不该跨会话出现的 | 「这句话只供当前会话使用：`<唯一标记>`」 |

按该端可观察的保存方式核对前置条件；无法确认时记录“前置条件未知”，后续未召回不能直接归因于记忆机制。

## 验收与发布诊断

以下项目用于开发验收、首次采用某条发布路径，或怀疑来源混淆、覆盖时；不是端接入前的资格测试。

### MV-04 · 知界回声隔离

**做什么**：先在干净会话跑一次自述倾倒；然后加载一份含独特标记的知界测试画像，再次要求倾倒，包的 `contour_context_loaded` 标 `true`。

**通过**：模型把那个标记归到"已加载的知界文件"，不是"原生长期记忆"。

**不通过**：记为**反馈回路高风险**——这一端的倾倒物需要整合时格外依赖差集来兜底。

### MV-05 · 项目文件与自定义指令隔离

**做什么**：在项目文件或项目指令里放一个独特标记，在该项目内和项目外分别倾倒。

**通过**：项目内看到时标为项目/工作区来源；项目外不声称它是全局记忆。

### 通道验证 + 一次完整同步

见 `protocol.md`。**能看见档案位置不等于能写进去**，必须实际提交并回读，以实际操作结果为准。

还要验证一次基础版本冲突：故意用过期的基础版本发布，看它是被拦下重来，还是直接覆盖了。**拦不下就说明这条发布路径不满足发布条件，不能用它发布统一结果**；改用其他满足条件的工具或路径。结果记录所用工具和日期，不作为该端的永久能力结论。

## 能力探测

### P-1 · 负面项原样喂进去会怎样

**测什么**：明确的否决、适用条件和理由在保存及召回后是否保留。结果用于判断是否需要 `load.md` 中的形态翻译。

**怎么测**：用**虚构的**否决事实（"不要使用 `<方案代号>`，因为 `<无害理由>`"），不做任何改写，原样喂进去。隔一段时间开新会话问它记住了什么。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 原样在，禁令强度没掉 | 本次观察未见改写 | 记录结果；后续使用原文并继续观察 |
| 变成了正面偏好（`Never explain basics` → `Prefers concise explanations`） | 本次观察出现改写 | 记录原始回答；必要时按 `load.md` 调整表达方式 |
| 完全没有 | 本次新会话未观察到 | 检查保存前提、加载条件和测试事实；不要仅据此判断内部机制 |

**测完清掉那条虚构否决**，别让它长期影响这一端的行为。

### P-2 · 项目文件在无关首问时是否生效

**测什么**：项目文件中的路由在未直接提及档案的首问中是否被使用。单次表现不能证明内部注入或检索机制。

**怎么测**：往 `routing.md` 里埋一条只有它知道的行为判据（例：「回答任何问题前，先用一句话复述我的问题」）。开全新会话，第一句问一个**跟档案完全无关**的问题，看它走没走那条判据。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 走了 | 本次会话中观察到路由生效 | 记录结果；再以不同题面复核 |
| 没走，但直接问「我的档案里写了什么」时读得到 | 本次未观察到自动生效，但文件可读 | 记录结果；根据实际需要选择项目文件或只读投影 |
| 连问都读不到 | 当前未能读取文件，原因待查 | 核对位置、权限及加载情况 |

**测完撤掉那条临时判据。** 它会改变这一端所有回答的方式，留着就是长期污染。

### P-3 · 记忆关注策略到底影响谁

**测什么**：`routing.md` 里那张记忆关注策略表有两个可能的消费者，效力完全不同：

- **平台的原生记忆系统**：观察相关内容是否在后续会话中可用，并记录保存方式是否可观察。
- **常驻上下文里的模型自己**——可观察它是否在相关场景中采用判据或提议同步（见 `drive.md`）

沟通路由的当轮表现与跨会话记忆召回分别记录。

**怎么测（两问，别混）：**

**第一问，测模型层**——在记忆关注策略里放一条独特判据（例：「凡是用户提到『试音』这个词，那句话连上下文一起记住」）。装好后开新会话，自然地说一句含那个词的话。**看模型在本轮收尾时有没有提议同步。**

**第二问，测平台层**——同一个会话结束后，另开一个新会话，问它记不记得跟那个词有关的事。

准备一条未写进记忆关注策略的相似事实作为对照。两条都被记住时，当前对照不足以分离平台原有行为与路由表影响，应记录并调整测试。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 模型提议了，新会话也记住了，且对照未被记住 | 本次观察同时出现两类表现 | 记录结果，必要时以更多场景复核 |
| 模型提议了，新会话没记住 | 本次只观察到模型层表现 | 保留记录，结合后续使用判断是否调整 |
| 模型也没提议，新会话也没记住 | 本次未观察到预期表现 | 记录条件；复核加载后再决定是否调整 |
| 对照也被记住了 | 对照无法分离影响 | 更换或补充测试事实后复测 |

### P-4 · 知识资产最小卡片能否跨会话召回

**测什么**：只喂“主题 + 权威资产位置 + 正面覆盖”后，这一端能不能在新会话想起资产的存在与位置，并在回答前实际读取；这不是 P-3 的记忆关注策略测试。

**怎么测**：选一条已登记资产，先把最小卡片喂进目标端。另选一个相近但并不存在的资产主题作为幻觉控制。随后开新的普通会话，依次测试：

1. 用语义近似的问题命中覆盖范围，但不说“以前”“你写过”，看它会不会想起并读取资产；
2. 用“我记得以前有一份那个东西”这类模糊指称，看它能否给出正确位置；
3. 问一个同主题但明确超出覆盖范围的问题，看它会不会先读取边界，再说明超出部分并另行查证；
4. 询问那个不存在的控制资产，看它会不会编出标题或位置。

| 看到什么 | 说明 | 接下来 |
|---|---|---|
| 记得正确位置，并在回答前读取 | 本次观察到资产被召回并读取 | 记录结果，后续以不同问题复核 |
| 记得主题但位置错误或过期 | 本次召回信息不准确 | 检查加载时的覆盖指令和取代语义 |
| 明说资产标题才想得起来 | 只有弱召回 | 记录结果；多端都如此再评估是否增加常驻提示 |
| 完全想不起来，但直接给位置后能读 | 本次未观察到自主召回 | 记录结果，不将其作为已验证能力声明 |
| 编出了不存在的控制资产 | 本次出现不正确资产信息 | 记录原始回答，避免将猜测写入路由 |

记录四次原始回答和工具调用。只看答案对不对不够——模型可能凭通用知识答对，却完全没走用户自己的资产。

## 深度诊断

出问题时才跑。

**MV-01 · 干净会话直接枚举**：关闭知界加载，全新会话跑 `assets/prompts/self-report.md`。看它能否导出会话前就存在的测试事实，或坦白"不能枚举"。**不得把当前提示里的措辞推断成用户画像。**

**MV-02 · 被动召回 vs 主动枚举**：不问"你记得什么"，给一个确实需要那条测试偏好才能做对的小任务。任务中使用了测试信息但 MV-01 没列出时，分别记录任务使用与枚举结果。**任务猜中不等于记忆可见**，两份结果分开记。

**MV-03 · 当前会话污染负向对照**：给一条临时事实并明确不要求保存，结束后新会话倾倒。临时标记不应出现。若出现，记录是平台真存了、会话泄漏还是模型猜的，**不能直接归类**。

**MV-06 · 作用域穿透**：同一问题分别在原项目、另一个项目、普通新会话里问。**不同范围表现不一致时，不许把它提升为全局记忆。**

**MV-07 · 更正传播**：保存一个事实，再用该端支持的方式明确更正，新会话倾倒。新事实被召回；旧事实要么消失、要么被明确标为旧版本，**不得两者并存当作当前事实**。

**MV-08 · 删除传播**：删除一条测试记忆后，新会话跑主动枚举和被动召回。仍出现就记录是删除延迟、作用域残留还是别的上下文来源。

**MV-09 · 负向约束与沟通偏好**：用包含测试主题的自然问题触发已保存的否决理由和沟通纠正。看它是只记住"不要做什么"，还是也保留了"为什么"和具体执行方式。

**MV-10 · 过期与矛盾识别**：准备有明确先后关系的旧状态和新状态，然后倾倒。能指出哪个是当前状态；无法判断时应同时列出并标冲突，**不得无声选一个**。

## 结果分级

| 结果 | 含义 |
|---|---|
| **未观察到持久召回** | 在记录的条件下，新会话未出现测试事实 |
| **前置条件未知** | 无法确认测试事实是否保存或测试环境是否满足要求 |
| **可被动召回** | 相关任务中会用记忆，但主动倾倒列不稳 |
| **可自述倾倒** | 能列出可访问记忆并基本区分来源，但不代表后台存储被完整导出 |
| **可核对导出** | 自述结果能跟该端的设置页或正式导出交叉核对 |

**分级描述能力，不代表产品优劣。** 知界的倾倒协议必须能适应"只能被动召回"和"只能自述"的端，不能假定所有端都有正式导出接口。

## 记录

结果写进 `state/endpoints/<endpoint-id>.md`，模板在 `assets/templates/`。至少要有：

- 产品与表面、模型、账号或项目范围
- 原生记忆是否开启：是 / 否 / 无法确认
- 测试前是否加载知界：按各项前置条件记录；原生记忆可见性测试不预先加载被测内容
- 实际使用的连接方式与工具，以及本轮检查的读、提交或发布结果
- 各测试项的结果 + **原始证据位置**
- 可见性结论、作用域结论、污染与回声风险
- 下一步

未运行的项目标为“未测”，不据此推断能力存在或不存在。

## 什么时候复核

配置、模型或平台能力变化后，先检查现有配置是否仍适用；只复核受影响的探测项。体检发现持续偏差时，结合原始回答决定是否补充 P-1、P-2 或 P-4 观察。
