# 问题反馈 · 技能缺陷的报告与提交

技能运行中发现疑似技能本身的缺陷时，起草一份不含个人内容的报告，经用户同意后提交给技能维护者。反馈不代替本轮的状态报告，也不改变任何档案内容。

## 什么时候起草

以下情况视为疑似技能缺陷：

- 技能自带的脚本异常退出或报出与输入无关的错误。脚本按设计给出的结论（如格式不合规、门槛未满足）不算缺陷。
- 技能各文件的规则互相矛盾，或按说明操作无法完成某一步。
- 技能要求的文件、模板或提示词缺失。
- 结果与技能说明不符，且已排除权限、网络、平台限制和用户数据本身的原因。
- 用户明确表示遇到了技能的问题，要求反馈。

权限不足、连接过期、网络失败、平台不支持某项能力，按 `drive.md` 第五节报告，不起草反馈。用户仍希望反馈时照常起草。

## 报告内容

| 项 | 写法 |
|---|---|
| 技能版本 | `SKILL.md` 元数据中的 `version` |
| 使用端 | 产品与表面，如 Claude Code、claude.ai 网页、Codex CLI、ChatGPT 网页 |
| 操作 | 初始化、倾倒、整合、发布、加载、查看状态或其他 |
| 期望结果 | 按技能说明应当出现的结果 |
| 实际结果 | 实际发生的情况 |
| 错误信息 | 报错原文或脚本输出，按下一节处理个人内容 |
| 复现条件 | 触发问题的步骤和条件；能否稳定复现 |
| 涉及的技能文件 | 相关的文件和章节名 |

## 删去个人内容

报告只描述技能行为，不包含用户资料：

- 不写记忆原文、画像、近期状态、倾倒包正文或档案中的任何条目。
- 不写账号、邮箱、姓名、仓库名称，以及路径中含个人信息的部分。
- 路径改写为相对档案根目录的路径，或用 `<已删除>` 占位。
- `store-id`、`endpoint-id` 含个人信息时改用 `<store-1>` 这类占位。
- 需要举例说明内容问题时，使用虚构内容，并注明是虚构的。

无法在删去个人内容后说明问题时，告诉用户这一点，由用户决定提交哪些内容。

## 询问与提交

1. 把完整草稿展示给用户，说明将提交到 `https://github.com/Alexu0317-FATHER/contour` 的公开 issue，所有人可见。用户可以修改草稿。
2. 未得到用户明确同意，不提交、不发送。用户拒绝后，本会话不再为同一问题询问。
3. 用户同意后：
   - 当前端具备用户已授权的 GitHub 操作能力时，在该仓库新建 issue，并把链接告诉用户。
   - 否则生成预填链接 `https://github.com/Alexu0317-FATHER/contour/issues/new?title=<标题>&body=<正文>`，标题和正文做 URL 编码，由用户打开后提交。链接过长无法打开时，改给 `https://github.com/Alexu0317-FATHER/contour/issues/new?template=bug_report.md` 并附上草稿，由用户粘贴。
4. 提交 issue 需要用户自己的 GitHub 账号。不向用户索取令牌、密码或 Cookie。用户没有账号时，保留草稿，由用户自行转交。

## 记录

在本端 `state/endpoints/<endpoint-id>.md` 的最近操作记录中写一行“问题反馈”：结果写 issue 链接、“已生成链接，待用户提交”或“用户未提交”。报告正文不写进档案。
