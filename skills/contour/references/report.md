# 汇报 · 向用户说明结果

初始化、同步和查看状态结束时，按本文格式向用户汇报。用户要一眼看出：哪个端补进了什么、哪里出了问题、需要他做什么。

## 写法

- 用日常语言和产品名（Claude Code、ChatGPT 网页端），不出现文件名、`store_id`、`dump_id`、版本号等内部标识。
- 每行用一句短话写具体内容，不写“3 条新增”这类计数；计数只在末尾总结一次。
- 没取到、失败、没读到，都作为表格中的一行写明原因，不另起段落。
- 冲突和问题写明来自哪个端、问题点是什么、需要用户做什么。
- 没有内容的表格整张省略。

以下示例内容均为虚构。

## 同步

**补进档案的内容**

| 来源 | 内容 |
|---|---|
| Claude Code | 开始做新项目 X，目标十月上线 |
| Claude Code | 更正：工作年限是 6 年，不是 5 年 |
| ChatGPT 网页端 | 没取到：连接已过期，需要重新连接 |

**需要你处理**

| 来源 | 问题 | 需要你做什么 |
|---|---|---|
| Claude Code / ChatGPT 网页端 | 居住城市一个记上海、一个记杭州，看不出哪个更新 | 告诉我以哪个为准 |

**各端读取情况**

| 端 | 情况 |
|---|---|
| Claude Code | 已写入它的记忆文件 |
| ChatGPT 网页端 | 还没读到；下次在那边说一声同步 |

末尾一句总结：本次补进几条内容；有没取到的端时列出名字。

## 初始化

| 项目 | 情况 |
|---|---|
| 档案位置 | 本机 `~/contour-archive` |
| 已接入 | Claude Code |
| 这次取得 | Claude Code 的记忆已取出，等第二个 AI 接入后生成档案 |
| 下一步 | 在第二个 AI 里说“把这里加入我现有的知界档案” |

档案位置连不上时，把“档案位置”一行写成连不上的原因，“下一步”写用户需要补齐什么，其余行省略。

## 查看状态

| 端 | 上次同步 | 最新档案 | 待处理 |
|---|---|---|---|
| Claude Code | 9 月 18 日 | 已读取 | 无 |
| ChatGPT 网页端 | 9 月 10 日 | 还没读到 | 连接已过期 |

有冲突或待确认事项时，接一张“需要你处理”表，格式同上。

## 状态措辞

“情况”“最新档案”两列按实际结果选用：

| 实际结果 | 写法 |
|---|---|
| 写入了该端的记忆文件，并回读核对 | 已写入它的记忆文件 |
| 本次对话读到了档案，平台记忆是否保存无法观察 | 本次对话已读取（平台记忆看不到） |
| 材料已送到，还没在对话中读取 | 已送达，还没读取 |
| 材料已准备好，等用户上传或粘贴 | 材料已准备好，等你上传 |
| 该端本轮未参与 | 还没读到；下次在那边说一声同步 |
