# 知界 Contour

从各端取得用户记忆，保留来源并整理，再向各端提供统一结果。目标是减少重复解释，使各端在相同情境下对用户形成较一致的理解。

## 零、请求范围

按用户意图选择操作；技能被选中不等于所有操作都获授权。具体触发规则见 `references/drive.md`。

- 仅表达困扰或询问知界用途：解释相关能力，必要时询问是否开始；尚未获授权时不访问私人档案。
- 查看状态：读取配置及相关记录并回答，不因此执行倾倒、合并或发布。
- 初始化、倾倒或同步：在明确请求或已确认的范围内执行相应工作，已确定的信息和授权直接复用。

## 核心规则

### 一个权威档案位置

`config.md` 存放在档案里，因此先确定档案位置：已接入的端从本端指令中的知界入口取得（见 `references/load.md`）；找不到入口时询问用户是否已有知界档案及其位置，没有档案时询问打算存放在哪里。连上后从 `config.md` 读取上次使用的接入方式。档案位置不能读写时，初始化、倾倒和同步都不开始。读取副本时核对对应版本；发布方式须满足 `references/protocol.md` 的发布条件，基础版本变化时重新读取并合并，避免覆盖其他端已保存的结果。

当前端按其可用能力执行本轮工作。已配置的接入方式失败时，保留原配置和已完成结果，先处理可恢复的原因，或在同一授权范围、同一档案位置和相同数据语义下改用当前可用的等效工具或通道。缺少必要连接或权限时，说明缺口并引导补齐；扩大账号、数据范围或发送对象前重新确认。用户资料保存到配置位置，不写入随技能分发的代码、模板或示例。

档案文件布局与发布条件见 `references/protocol.md`。具体操作可以使用已配置的实现，也可以使用能提供同等结果的其他可用工具；以实际操作和回读结果为准，不以模型自述代替。

### 分别记录取得、整理和加载

本端记忆、当前会话信息、外部资料和知界送回的内容分别标明来源。整合后让目标端读取相关结果，并按该端可用的记忆机制处理更正和新增内容。

分别记录档案保存、材料送达、当前会话读取和原生记忆状态。平台内部状态无法观察时写“无法确认”；模型口头表示“记住了”不证明持久保存。

### 保留更正关系，以表现评估一致性

对过期或错误信息记录取代、更正和撤回关系，送回时明确相关变化。无法判断的矛盾并列保留，交由用户确认。

一致性评估关注各端在同一场景下是否能使用相关信息并采取适当的沟通方式，不要求记忆条目或回答逐字相同。行为评估见 `references/audit.md`，平台机制诊断见 `references/probe.md`。

## 记忆存储与使用端

**记忆存储**是 AI 实际保存用户记忆的位置，分本地（本机的记忆文件或目录）和云端（某个账号在平台上保存的记忆）。这个分类只描述位置；采集方式由执行者根据用户授权和该存储当前实际可访问的途径选择，授权不等于已经具备访问能力。**使用端**是需要读取统一结果的产品入口。

倾倒、首发门槛和倾倒游标按记忆存储计算；送达、读取和原生记忆状态按使用端记录。同一存储由哪个端、用什么工具读取，不改变内容归属。每个使用端默认有自己的记忆存储，不按账号或厂商推定共用。标识见 `references/protocol.md`。

## 知界档案内容

以下是当前文件布局；具体结构和字段见 `references/protocol.md` 与 `references/schema.md`，空白模板在 `assets/templates/`。

| 内容 | 用途 |
|---|---|
| `config.md` | 档案位置、接入方式、纳入的记忆存储与使用端、权限与初始化状态 |
| `profile.md` | 稳定背景、能力、偏好和判断方式 |
| `now.md` | 带时间信息的近期状态 |
| `routing.md` | 沟通路由与记忆关注策略 |
| `sources.md` | 快变事实的查询入口，以及已保存知识资产的位置 |
| `evidence.md` | 结论依据、来源及取代或撤回关系 |
| `tests.md` | 独立行为评估的题库和记录 |
| `state/stores/<id>.md` | 每个记忆存储的采集记录与倾倒游标 |
| `state/endpoints/<id>.md` | 每个使用端的送达、读取与加载状态 |
| `dumps/` | 倾倒包及消费记录 |
| `review/` | 冲突、待确认、更正、撤回和失败记录 |

文件名使用通用名称，不绑定具体用户。

`routing.md` 指导模型如何沟通、关注哪些记忆；`sources.md` 指导模型到哪里查询。涉及最新事实时按来源路由查证，不能以旧的 `now.md` 摘要代替当前证据。

知识资产区只登记已有、可跨会话复用的外部资料指针，不接管其内容和写回，规则见 `references/consolidate.md`。

将简短的 `routing.md` 和档案读取入口接入当前端可用的指令位置，其余内容按需读取。加载方式及结果记录见 `references/load.md`。隐藏题库不进入被测身份的上下文。

## 判断当前状态

先连上档案位置，再读取已有配置和记录，根据用户请求决定下一步，不要求用户回忆此前操作。

- 找不到档案位置：询问用户是否已有知界档案；有则连接，没有则先确定存放位置，再开始初始化。
- 档案位置连接失败：保留原配置和初始化状态，先尝试恢复或改用等效通道；仍无法读写时报告失败原因、仍然有效的结果和需要用户处理的事项，然后停止；不倾倒，也不据此重新建档。
- 当前端尚未登记：登记该使用端及其记忆存储，完成该存储的基线倾倒，再提供当前统一结果。
- 存在未提交包或未消费包：按状态和消费记录续办，避免重复提交或消费。
- 当前端尚未读取最新统一版本：先保护本端新增信息，再加载更新。

仅缺少完成本轮操作所必需的信息时查询或向用户确认。查看状态不触发上述写入动作。

## 同步执行

用户请求同步后，当前端执行以下有依赖关系的操作：

1. 连接档案位置并确认能读写：优先使用已配置的接入方式，不可用时按上文选择等效方式；仍无法读写时按「判断当前状态」报告并停止。连上后读取配置和状态。
2. 按 `references/drive.md` 第二节确定本轮采集范围：依据用户本轮请求和 `config.md` 中已保存的授权。已登记不等于本轮已授权采集；配置中已明确的授权直接复用，不重复询问。
3. 在加载本轮新统一材料之前，对范围内每个记忆存储分别取得新增、更正、失效或撤回信息，各自保留 `store_id` 与 `collected_via`。某个存储本轮取不到时记录缺口和原因，不写成“没有变化”，也不阻塞其他存储。没有变化的存储不创建增量包。
4. 将各包提交到各自存储的收件区；失败时按 `references/drive.md` 第五节恢复或改用等效通道，仍未完成时在当前实际可写的位置保留包和未提交状态。
5. 读取当前统一版本、未消费包和消费记录。
6. 当前执行者有满足发布条件的方式时按 `references/consolidate.md` 统一整合；没有时保留待处理状态并说明缺口，仍可读取已发布结果。
7. 发布前检查基础版本；发生变化时重新读取和合并，按 `references/protocol.md` 保存完整结果及消费记录。
8. 让当前端读取 `routing.md` 与本轮相关变化，并按 `references/load.md` 更新加载内容。
9. 更新各相关存储和本端的状态，按存储分别报告已取得、未取得及原因，以及完成、跳过、失败和待办事项。

本轮范围包含当前端所用的存储时，先取得它的增量再加载新结果，用于减少将知界送回内容重复视为独立来源的回声；来源识别仍按倾倒和整合规则执行。

本地钩子或平台自动化如经用户启用，复用同一套授权和数据规则，见 `references/drive.md`。

## 初始化

### 输入与配置

先确定档案位置，并确认当前端能读写；不能读写时说明缺什么，停在这一步，不开始倾倒。已有知界档案时读取其 `config.md` 并继续沿用，向用户说明已经接入的使用端、记忆存储和当前初始化状态。

位置确定后，复用用户已提供的信息，只补齐纳入的使用端及其记忆存储、现成资料、授权范围和必要接入信息。配置写入 `config.md`。

已有个人画像作为一个来源参与比较，依据内容和时间判断有效性，不预设它正确或过期。先取得各记忆存储的基线，再与已有画像比较，减少画像对本端自述的影响。

每个纳入的记忆存储完成一次基线倾倒，方法见 `references/dump.md`；一次操作可以采集授权范围内的多个存储，采集方式按 `references/drive.md` 第二节选择。暂时取不到的存储标为待完成。没有可输出记忆也是合法结果；仅保留可确认的信息与未知项，不以推断补齐人格画像。

### 首次发布门槛

首次发布需要至少两个不同、已登记的记忆存储各有一份格式合规的 baseline。同一存储的多个包只算一个，无论由哪个端读取。能核对出自某个存储的记忆文件、官方导出或接口返回可以作为该存储的 baseline；用户自己的画像，以及来源或日期无法核对的旧资料，不算记忆存储。格式合规的空 baseline 可计入，但仅表示本次未提供记忆，不证明后台完全没有记忆。

门槛按三项核对：包是否格式合规（校验项见 `references/protocol.md`）；合规 baseline 按存储标识去重后是否来自至少两个存储；这些存储是否已登记在 `config.md`。不合规或 `dump_id` 撞号的包不计入门槛、不进入本轮整合，记录原因后交用户处理；它们不阻断其他相互独立的有效包。

v1 旧包按端记录，须先按 `config.md` 的使用端表对应到 `store_id` 再去重计数；对应关系无法确定时，该包的存储身份待确认，不计入门槛，也不能据此宣称存储数量已满足。

本地能运行 Python 时，可用脚本完成前两项；有 v1 旧包时逐个给出对应关系：

```text
python scripts/validate_dump.py --cold-start-ready <档案根目录> [--store-map <endpoint-id>=<store-id> ...]
```

脚本分别报告“格式检查”和“首发门槛”：格式检查通过只说明包合规；`[READY]` 只说明合规 baseline 来自至少两个不同存储，存储是否已登记仍要对照 `config.md`。不能运行脚本时，用其他能给出同样结果的方式逐项核对，并记录核对依据。

门槛未满足时，本轮的准备结果只包括配置、存储与使用端状态和未消费包；不生成草稿画像，不生成或发布 `profile.md`、`routing.md`、`sources.md`、`evidence.md`、`tests.md`，不写消费记录。向用户说明已取得哪些存储，以及尚未形成跨端统一档案。

该门槛只用于首次统一发布；之后单个存储的 incremental 可单独参与更新。

### 整理与加载

门槛满足后按 `references/consolidate.md` 整理，并生成路由与来源入口：

- 画像结论可追溯到依据；原生记忆、外部资料、用户确认和推断分别记录。
- 根据条目时间和更正关系处理变化；无法判断的冲突进入 `review/`。
- 知识资产区没有符合条件的资料时保持为空。
- 按 `references/load.md` 提供统一结果，并记录实际加载状态。

接入以本轮实际读取、提交、发布和回读的结果为准。需要开发验收、平台机制诊断或一致性检查时，分别使用 `references/probe.md`、`references/audit.md`；它们不是初始化或同步的前置步骤，结果与同步记录分开。

### 完成状态

初始化状态分为等待第二个记忆存储、暂定版本和冷启动完成，各自的可核对条件见 `references/schema.md` 的 `config.md` 一节。仍有存储待完成时，已发布结果标为暂定版本并说明缺项。

这些状态只说明基线取得和统一版本保存的进度。各使用端的送达、当前会话读取和原生记忆状态按使用端记录和报告，不能由状态词推断。向用户说明跨端同步已经可用时，还需要参与端读取同一统一版本，且倾倒内容不依赖用户手工搬运；未满足的部分分别说明。

材料送达或基线齐备不能单独证明各端行为已经一致，相关结论以独立行为评估为依据。

## 档案写作与用户控制

中性记录用户信息，不添加价值评价或诊断。不确定内容明确标注；依据和事实时间不足时保留待确认状态。

按用户确认的可见范围保存资料。用户提出更正、撤回或脱敏时，按 `references/consolidate.md` 处理并说明实际影响范围。

## 问题反馈

遇到疑似技能本身的缺陷时（例如脚本异常退出、规则互相矛盾、按说明无法完成），先完成本轮的失败报告，再按 `references/feedback.md` 起草一份不含个人内容的反馈，询问用户是否提交。未经用户同意不发送；权限、网络、平台限制等环境原因造成的失败按 `references/drive.md` 第五节报告，不作为技能缺陷。用户主动要求反馈问题时也使用该流程。

## 参考文件

仅加载当前任务需要的内容：

- `references/protocol.md`：数据格式、档案布局、包校验、包身份、消费记录和发布条件。
- `references/drive.md`：请求范围、执行上下文、自动化和失败处理。
- `references/dump.md`：基线与增量倾倒、来源区分和采集方式。
- `references/consolidate.md`：分层、去重、冲突处理、路由、更正与撤回。
- `references/load.md`：指令加载、材料送回和记忆状态记录。
- `references/probe.md`：开发验收与按需平台诊断。
- `references/audit.md`：独立行为评估、题库隔离和结果记录。
- `references/schema.md`：字段与写作规范。
- `references/feedback.md`：技能问题反馈的判断、脱敏和提交方式。

提示模板在 `assets/prompts/`，文件模板在 `assets/templates/`。`scripts/` 中的生成与校验脚本是 `references/protocol.md` 规则的可选本地实现。
