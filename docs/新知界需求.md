# 知界（Contour）需求

> **这份文档是写给我自己的。** 别人想知道这技能好不好用，看 README，不看这里。
>
> **这里不写平台能力结论。** "某个端能不能做某事"随时会翻案，那些话在 [`平台能力实测.md`](平台能力实测.md)。本文只写"当某个端具备某能力时，产品该怎么做"。
>
> **这里也不写当前进度。** 谁测过了、哪项没过、哪个文件还没改，在 GitHub Issues 和 [`NOTES.local.md`](NOTES.local.md)。

## 一、我要解决什么

我同时在网页版 ChatGPT、Claude.ai、Claude Code、Codex、VS Code 里跟 AI 聊天。每一端都存了一份关于我的记忆，每一份都只见过我的一部分，而且互相不知道对方存在。

结果就是：在网页端聊了一个月的事，换到 Codex 像没发生过。我得重新解释一遍自己——在做什么项目、不想听什么话、判断一件事的方式。**记忆变成了平台的转移成本。**

我要的效果一句话：

> **换端不用重新解释自己。**

注意这不是"各端记忆一模一样"。各家的记忆都是黑盒，字节级一致做不到，也没必要。我要的是**同一个问题，在不同端得到同类反应**。痛的是行为，不是存储。

## 二、怎么做

三步，循环跑：

| 步 | 做什么 |
|---|---|
| **倒出来** | 让每一端把它记得的关于我的东西吐出来 |
| **理清楚** | 去重、合并、冲突并列保留、按变化速度分层 |
| **喂回去** | 把整理结果送回每一端，让它按自己的机制吸收 |

**关键在"循环"。** AI 是渐进调用记忆的——问一次不会把知道的全吐出来，能吐多少取决于当时问了什么、上下文里有什么。所以**单次导出不完整是正常的，不是失败**。跑的次数多了，各端知道的东西逐渐重叠，最后趋同。

这是整个设计的核心假设，也是最该被验证的一条：**趋同靠的是时间累积，不是单次的完整性。**

但要清楚，这个循环**既能收敛也能发散**。发散的机制很具体：各端原生记忆是只加不删的，旧的错条目不会因为喂了新的就消失。"他在找工作"和"他入职了"并排躺着，召回哪条看运气，下次倒出来更乱。所以喂的时候必须点名要覆盖哪条，不能只交新的。

## 三、已经有 profile 文档的人

我自己就有一份，写了很久，很长。它**不是这个技能的替代品，也不是起点，是原料之一**：

- 它已经过期了，而且没有一条带时间戳让人察觉；
- 它太长，没有任何一端能整份吃下去；
- 它只反映我以为的自己，各端记得的是另一回事。

所以流程不变：先倒，再把这份文档当成"某一端的导出物"平等参与合并，不给它特权。

没有这份文档的人照样能用，只是少一份原料。

## 四、几条不能动的设计

这些是我们自己定的产品规则，跟平台能力无关，平台怎么变都不改。

### 1. 一个信源，副本永远不是权威

档案只有一份是真的，放在我本机。各端读到的都是它的投射。

副本可以有——Codex 那边写进 `AGENTS.md` 的那段就是副本。但**副本一旦能被独立修改，就会各自演化，然后静默分岔**，到时候没人知道哪份对。所以副本一律带生成日期、每次同步重新生成、倒记忆的时候跳过。

**同一时间只能有一个程序在改档案。** 我在 PowerShell 里开着 Claude Code，Codex 那边也开着，两边同时往里写就完了。谁在改，得有个明确的占用标记，另一个看见了就等着或者只读。

### 2. 知界不持有记忆，只刷新记忆

每一端本来就有自己的记忆系统在工作。知界不跟它们抢活，也不取代它们——**它们是下游，档案是上游**。

知界只做两件事：把"该怎么跟我说话"放进各端每轮都看得见的位置；把整理结论送到各端面前，让它自己按自己的机制归类保存。

**具体存什么、怎么压缩，是各端自己的事。** 知界给材料和关注方向，不下指令，也不要求任何端绕过它自己的规则。

### 3. 只有一份东西常驻，其余按需读

"该怎么跟我说话"必须每轮都在——等某个话题匹配上才加载就晚了，前面几轮已经用错语气说完了。

其他的（详细画像、当前状态、证据出处）全部走指针按需读。**全塞进常驻上下文会挤掉我真正要干的活，而且档案越完整挤得越狠——做得越好越难用，这个设计会自己咬自己。**

### 4. 分层按变化速度，不按主题

一份档案变馊，通常不是写错了，是把有保质期的东西写进了没有保质期的层。所以：

- 一年后大概率还成立的 → 慢变层
- 会变的、或者拿不准会不会变的 → 快变层，**强制带时间戳**
- 原始素材和出处 → 证据层

拿不准就往有时间戳的那边放。**放错方向的代价不对称**：快变层里的过期条目会自己暴露，慢变层里的过期条目会一直以满分自信被各端引用。

### 5. 冲突不许偷偷选一个

两条信息打架，有条目级的时间依据就按依据裁；没有依据就**两条都留着，标成待确认，交给我**。

替我做无声的裁决，是在偷我的数据主权。

### 6. 不许伪造成功

这几件事必须分开报，不能合并成一句"同步成功"：

- 从某个端倒出来了
- 进档案了
- 影响了哪一版
- 给某个端的那份生成了
- 送到那个端了
- 那个端这次会话读到了
- 那个端的后台记忆吸收了

**它们可以同时停在不同位置，这是合法结果。** 比如"本机已经整理完提交了，ChatGPT 那份还没送过去"——照实说，不许说成同步成功。

最后一条尤其要小心：**模型说"我记住了"不算数**。那只证明材料送达。真验证要隔一段时间开个新会话再问。

### 7. 别把自己写回去的东西当成新发现

上一轮喂给 Claude 的内容，下一轮它可能原样吐回来。**重复出现不增加可信度。**

判不出来就标不确定，绝不能靠"出现了两次"给一条信息加分。

## 五、走过的弯路

留着是为了不再走一遍。

### 第一次：让每个端都去写同一个 GitHub 私仓

想法是把私仓当共同工作台，各端把记忆倒进去。实际做下来，为了支持多个端同时写，协议里被迫塞进条件写入、原子多文件发布、并发冲突恢复……复杂度全花在"防止两个端互相覆盖"上，而这跟我要解决的问题一点关系都没有。

**教训：多写者是被架构选择逼出来的复杂度，不是需求。**

### 第二次：让 Codex 当唯一的操作中枢

选它是因为它有内置浏览器、还能在里面开 Terminal 跑 Claude Code。后来发现内置浏览器登录有问题，Terminal 那边也读不到我跟 Claude Code 聊了什么。选它的两个理由都塌了。

**教训：不要围绕某个 App 的特殊能力设计架构。** App 的能力说没就没，而"我本机上跑着某个能读写文件的 AI"这件事不会变。

**现在的位置**：谁在本机跑、谁就能整理档案。Codex 是端之一——它切到 ChatGPT 模式能看到网页版的全部会话和 Projects，这是它的价值——但它不是中枢，不整理档案也照样能跑。

## 六、现在做什么

**目标用户**：跟我一样跨端用 AI 的人。至少两个端，本机至少有一个能读写文件的 AI。

**要打通的端**：网页版 ChatGPT、Claude.ai、Claude Code、Codex、VS Code / Zed 里的本地 Agent。

各端接进来的方式不强求一致——能直接读写本机文件的走文件，不能的走各自的通道。**通道是什么，取决于那个端当下的能力，查 `平台能力实测.md`。**

### 现在不做

- 多台设备同时跑同一个知界实例
- 无人看着的自动登录、上传、发送、定时同步
- 承诺各端后台记忆逐字一致
- 替代项目管理、日历、知识库
- 重建一个通用记忆 API 或向量库
- 把网页自动化包装成稳定后台接口

## 七、怎么算做完了

按顺序，前面的没达到就别谈后面的。

**能开始用**：

- [ ] 至少两个端各自成功倒出一次记忆，进了同一份档案
- [ ] 我没有被要求手工复制粘贴大段内容
- [ ] 各端读到的是同一版

**冷启动完成**：

- [ ] 每个纳入的端都倒过一次，一个不缺
- [ ] 整理时能分清哪些是端原本记得的、哪些是知界自己上轮写回去的
- [ ] 问到"最近怎么样"这类快变问题时，会去查权威来源，而不是复述旧摘要
- [ ] 自动解决不了的冲突进了待确认，没被静默覆盖

**产品成立**（这条才是真的验收）：

- [ ] 跑过若干轮之后，我在一个端聊过的事，换到另一个端能被提起来
- [ ] 各端的互补信息缺口在缩小——**不要求各端逐字复述同一份记忆**

**只倒了两个端就宣布完成是自欺欺人。** 剩下几个端的独有记忆一条都没进来，而"每端只见过我的一部分"正是我要这个技能的原因。

## 八、会变的东西

### 平台能力

现在做不到的，不代表以后做不到。各端的记忆导出接口、文件读写通道、自动化能力都在变。

所以：**任何"某端不支持某功能"的结论都必须带日期，写在 `平台能力实测.md`，不许写进本文当成永久事实。** 需求文档里只写条件句——"当某端能读本机文件时走 A，不能时走 B"。

### 路线图

- **自动跟踪 OpenAI 和 Anthropic 的 changelog / 功能发布**，用来触发能力结论复审。上面那条纪律靠人执行迟早会漏，这个需求就是把它自动化。
- 其他已确认但不进当前范围的能力，在 [`roadmap/`](roadmap/)。
