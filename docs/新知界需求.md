> **本文是唯一活的产品需求文档。** 本次架构基线自 2026-08-14 起生效，背景、证据和影响范围见 [GitHub Issue #17](https://github.com/Alexu0317-FATHER/contour/issues/17)。
>
> **2026-08-16 修正**：原文把 Codex 写成"唯一协调者兼唯一写入者"、并把它当作唯一网页桥接者。这两条已收窄为：**Codex 模式是默认本地协调者**；**ChatGPT 模式是 ChatGPT 会话与 Projects 的权威访问界面**；**每笔事务只有一个通过资格门槛并持锁的本地写入者**。名称约定见下一节。本次修正的完整决策记录以 Issue #17 及其修正案评论为准。
>
> 本文描述“接下来要做成什么”，不把尚未实现或尚未验证的能力写成现状。`skills/contour/` 与其他活文档仍含上一版 GitHub 多写者架构；在后续 Issue 完成前，它们是待迁移实现，不是本文的反证。

## 一句话定义

知界是一个以**用户本地 Git 仓库为统一记忆锚点**、由**每轮一个经验证的本地执行者持锁写入**的跨端记忆协调技能。

**Codex 模式是默认的本地协调者**；**ChatGPT 模式是 ChatGPT 会话历史与 Projects 的权威访问界面**。两者都是同一个 ChatGPT 桌面应用的顶层入口，不是两个互不相关的产品。

它从用户明确纳入的 ChatGPT、Claude.ai 和本地 Agent 中取得可见信息，保留来源并完成去重、冲突处理和重组，再把适合各端使用的结果送回去。知界提供的是用户可审查、可迁移的统一记忆资产及其投影，不承诺直接控制各平台不可见的原生记忆数据库。

## 名称约定

本文之后出现的每一个名称都按下表理解。**把产品、模式和内置浏览器混为一谈，是这份文档上一版最主要的错误来源**，所以先把名字钉死。

| 名称 | 指什么 | 本文中的职责 |
|---|---|---|
| **ChatGPT 桌面应用** | OpenAI 的 Windows / macOS 桌面产品外壳 | 承载 ChatGPT 模式、Codex 模式、内置浏览器与集成 Terminal。它是壳，不是执行者 |
| **ChatGPT 模式** | 桌面应用顶层入口之一 | **ChatGPT 历史会话与 Projects 的权威访问界面**；在此运行知界 Skill 生成或接收 ChatGPT 端交换物。Skill 调用入口是 `@` |
| **Codex 模式** | 桌面应用顶层入口之一 | **默认本地协调者**：本地仓库、文件、Git、工作区检查、审计；也是当前唯一已验证的受监督浏览器自动化执行端。Skill 调用入口是 `$` |
| **内置浏览器** | 桌面应用内的浏览器工具面板 | 网页端到端验证、受监督的下载与上传。**它不是 ChatGPT 模式**，也不自动继承桌面应用的登录态 |
| **本地执行者** | 任何通过本地执行资格门槛的本地运行环境 | Codex 模式、Claude Code、VS Code / Zed 中的本地 Agent 都是候选。资格由门槛决定，不由产品名决定 |

`[官方文档 2026-08-16]` 名称层级与 `@` / `$` 调用方式见 `平台能力实测.md` 的「ChatGPT 桌面应用的模式划分」一节。

### 三条由名称直接推出的边界

1. **ChatGPT 模式与 Codex 模式看到的东西不一样。** Codex 模式没有 ChatGPT 模式那份历史会话 / Projects 侧栏。要读 ChatGPT 会话或 Project，就到 ChatGPT 模式去读，不要绕内置浏览器。`[用户观察 2026-08-16]`
2. **内置浏览器登录不是知界使用 ChatGPT 会话和 Projects 的前置条件。** 内置浏览器当前处于未登录状态，这不阻塞知界——ChatGPT 端的读取路径走 ChatGPT 模式。内置浏览器保留给网页交互与端到端验证。`[实测 2026-08-16]`
3. **任何平台名或模式名本身都不授予 Vault 写入资格。** "它是 Codex"、"它是本地 IDE"、"它能看到本地项目"都不构成通过证明。写 Vault 必须先通过本地执行资格门槛，再取得事务锁。

## 为什么改变架构

上一版架构要求所有端都能读写同一个 GitHub 私仓，并允许任意端临时接任协调。实际推进后，这个前提没有成立：

- ChatGPT 能看到 GitHub，不等于能按知界协议稳定创建倾倒包、回读并完成安全发布；
- Claude.ai Chat、Projects 与 Code 标签是不同环境，Code 标签不是 Claude.ai Chat 的可写 GitHub 通道，也不能代表两边记忆互通；
- 为了支持多个写入者，协议被迫引入分支引用竞态、条件写入、原子多文件发布、共享 clone 并发和多套失败恢复；
- 大量本可从官方资料或现有工具确认的能力，被错误地推迟成用户安装后的测试；
- 用户仍看不到安装后的真实交互，只看到内部状态机和 GH-XX 测试编号。

与此同时，ChatGPT 桌面应用已经具备成为本地控制面的关键条件：**Codex 模式**能在本地项目中工作，能访问本地文件和 Git，并能通过受监督的浏览器操作完成网页端下载和上传；**ChatGPT 模式**能直接展示 ChatGPT 历史会话与 Projects，不需要任何浏览器登录。把协调权收回本地，能移除上一版最脆弱的“所有端都必须成为仓库写入者”假设。

因此，本次改变不是更换传输工具，而是改变产品边界：

- 从“每个端都运行完整同步状态机”改为“每个端只负责输入或接收，本轮持锁执行者负责完整状态机”；
- 从“GitHub 私仓是所有人的共同工作台”改为“本地 Git 是唯一事实源，远端仓库只是可选备份或跨设备通道”；
- 从“写不进 GitHub 就未接入”改为“只要能可靠地产出或被读取、并能接收投影，就可以作为受支持端”；
- 从“尽量刷新各端原生记忆”改为“先保证统一资产和当前上下文投影可靠，再单独验证原生记忆是否吸收”。

## 当前产品范围

### 适用对象

当前 MVP 面向同时使用多个 AI 端、并拥有 ChatGPT 桌面应用本地工作环境的个人用户。用户至少需要：

- 一个可运行知界协调流程的本地项目（当前默认在 **Codex 模式**中运行）；
- 至少两个准备纳入统一理解的端或信息来源；
- 对被读取的会话、文件和账号拥有合法访问权；
- 愿意在网页端登录、授权、确认上传或发送等必须由本人完成的动作。

**ChatGPT 桌面应用是当前架构的产品依赖。** 它同时提供两样东西：Codex 模式给出本地协调面，ChatGPT 模式给出 ChatGPT 会话与 Projects 的权威访问面。缺少桌面应用的纯网页用户不属于当前 MVP。

**但"产品依赖"不等于"唯一执行者"。** Codex 模式是默认协调者，不是永久唯一写入者——本地写入资格由资格门槛与事务锁决定，见后文。

### 当前要打通的端

| 端 / 模式 | 在知界中的角色 | 当前证据边界 | 纳入 MVP 的条件 |
|---|---|---|---|
| **Codex 模式** | 默认本地协调者；可持锁写入者；当前唯一已验证的受监督浏览器自动化执行端；当前端消费者 | 已能操作本地项目、Git 与工作区；隔离 canary 已通过本地事务能力 `[实测 2026-08-16]`；**但生产 Skill 仍是旧的 GitHub 多写者协议，未迁移** | 完成新状态机、事务锁互斥与分项回执验收 |
| **ChatGPT 模式** | ChatGPT 历史会话与 Projects 的权威访问界面；用 `@` 运行知界 Skill 生成 / 接收 ChatGPT 端交换物 | 侧栏可见网页版历史会话与 Projects `[用户观察 2026-08-16]`；ChatGPT 与 Codex 共用同一份 Skill、分别用 `@` / `$` 调用 `[官方文档 2026-08-16]`；**能否直接写本地 `exchange/from/` 仍 `[未验证]`** | 指定范围读取、交换物生成路径与投影接收通过验收；写交换目录须先做一次无真实数据的 canary |
| **Claude Code** | 候选本地执行者；来源端与投影接收端 | 隔离 canary 中锁、校验、合并、提交、回读均通过 `[实测 2026-08-16]`；**Skill 自动发现未通过；跨应用事务锁 `[未验证]`；生产 Skill 未迁移** | 通过资格门槛全部十项 + 跨应用锁互斥实测；未通过前只写自己的交换目录 |
| **VS Code / Zed 中的本地 Agent** | 候选本地执行者 | 十项资格门槛**全部 `[未验证]`**：技能发现路径、技能目录归属、事务锁行为均未测 | 同 Claude Code。**不因"是本地 IDE"自动获得资格** |
| **Claude.ai** | 通过 Skill 生成倾倒包的上游来源，也是文件投影接收端。**永不担任协调者或统一资产写入者** | 官方支持 Skills 和文件生成 `[官方文档]`；知界包的下载、导入、回传闭环尚待实测 | 端到端包交换通过验收 |

表中的“目标角色”不是“已经支持”。任何组合只有通过本组合的完整验收后，README 才能写成可用。

**表里的模式名不构成写入资格。** ChatGPT 模式与 Claude.ai 属于网页 / 会话界面，永远不能成为协调者或统一资产写入者；Codex 模式、Claude Code、VS Code / Zed 中的本地 Agent 都只是**候选**，逐项通过资格门槛并取得事务锁之后才能写。

### 暂不进入当前 MVP

- 无 ChatGPT 桌面应用的纯网页组合；
- 把 GitHub、Google Drive、Notion 当作所有端共同写入的统一锚点；
- 多台设备同时协调同一个知界实例；
- 无人监督的浏览器登录、上传、发送或后台定时同步；
- 对所有 IDE、Agent 和模型做未经验证的泛化支持；
- 承诺各平台隐藏的原生记忆逐字一致或已经写入；
- 用知界替代项目管理、日历、知识库或完整的外部记忆服务。

## 产品对象与职责

### Codex 模式：默认本地协调者

**Codex 模式当前独有的能力**（尚无第二个已验证的执行端）：

- 受监督的浏览器自动化：打开页面、下载文件、上传文件；
- 找到下载文件、校验并转移到知界交换目录；
- 本地仓库与工作区检查、Git 操作、证据归档与最终验收。

浏览器下载到本地交换目录这一段已经跑通：真实下载事件、定位实际路径、转移后 SHA-256 与内容均未变。`[实测 2026-08-16]`

**Codex 模式不是唯一网页桥接者。** ChatGPT 历史会话与 Projects 的权威访问界面是 **ChatGPT 模式**，那条路径不经过内置浏览器，也不需要内置浏览器登录。把两者混成"只有 Codex 能碰网页端"，会逼出一条本来不必要的浏览器登录依赖。

### 本轮持锁执行者：唯一规范写入者

以下动作由**本轮取得事务锁的那一个本地执行者**完成，不绑定产品名：

- 创建和维护知界本地实例；
- 导入各端倾倒包并校验来源、完整性和重复提交；
- 读取当前统一资产、处理冲突并生成新版本；
- 修改 `profile.md`、`now.md`、`routing.md`、`sources.md`、`evidence.md`、消费清单和端状态；
- 为不同端生成投影；
- 提交统一资产的 Git 版本；
- 重新读取实际提交结果；
- 对本轮每个动作给出可验证回执。

Codex 模式是**默认**持锁执行者。Codex 用量紧张、未开机，或用户明确交接时，其他**通过资格门槛的本地执行者**可以取得本轮事务权，完成合并与 Git 写入。

**网页与会话界面永远不能成为协调者或统一资产写入者。** 这不是当前实现限制，是产品约束：它们没有可验证的本地事务锁，也没有可审计的本地 Git 提交。

#### 本地执行资格门槛

某个本地运行环境只有**逐项验证**以下十项后，才能担任本轮合并执行者：

1. 能发现并完整加载当前知界技能；
2. 能读取本地 Vault 与本端交换目录；
3. 能创建并持有本地事务锁；
4. 能在开始前检查 Git 工作区、当前 commit 和未完成事务；
5. 能校验倾倒包 schema、来源、唯一标识和完整性；
6. 能执行统一的去重、消回声、冲突保留和信息分层规则；
7. 能修改统一资产、消费清单、端状态和投影；
8. 能创建可审计的本地 Git commit；
9. 能重新读取实际提交结果；
10. 能把"已导入、已消费、已提交、投影已生成、已送达、已加载、原生记忆吸收"分别回执。

**平台身份、模式名或"它是本地的"都不是通过证明。** 每一项的验证结果按端记录在 `state/endpoints/<endpoint-id>.md`，未验证项写 `[未验证]`，不写空白。

当前逐端状态：

| 候选执行者 | 门槛结果 |
|---|---|
| Codex 模式 | **第 5 项部分通过**——完整性同样只靠脚本外的 SHA-256 比对，不是 validator 提供的；**第 1–4、6–10 项通过** `[实测 2026-08-16]`。**不等于生产 Skill 已迁移** |
| Claude Code | 第 1 项自动发现**未通过**（技能未安装到可扫描路径）；**第 5 项部分通过**——schema / 来源 / 唯一标识由生产 validator 校验通过，完整性只在 canary 里靠外部 SHA-256 比对验证；其余各项在隔离 canary 中通过 `[实测 2026-08-16]`。**不等于生产 Skill 已迁移** |
| VS Code / Zed 中的本地 Agent | 十项全部 `[未验证]` |

**第 5 项的完整性缺口在协议层，不在某一端**：当前校验脚本只做 schema、身份和位置检查，不校验内容。因此"哈希由谁生成、保存在哪、谁负责在导入前核对"必须在协议里定死——在那之前，任何执行者的第 5 项都只能记为部分通过。

#### 每笔事务只有一个持锁写入者

- 用户或主控明确指定本轮由谁执行；
- 执行者取得本地事务锁后，其他本地执行者只能等待或只读；
- 完成、失败或放弃时释放锁并留下状态；
- **不允许 Codex 模式、Claude Code、VS Code 或 Zed 中的本地 Agent 在同一工作树中同时编辑或提交**；
- 互斥对象是"所有本地执行者"，**不限于同机的多个 Codex 任务**；
- 所有本地执行者必须使用**同一把事务锁**，不得各自实现互不可见的锁。

**当前的证据空洞必须写明**：Codex 模式与 Claude Code 各自只验证过"自己与自己的另一个进程"之间的互斥；**跨应用互斥（Codex 持锁时 Claude Code 被拒、反之亦然）仍是 `[未验证]`**。在这项实测通过之前，不得让两个不同的本地应用在同一个 Vault 上并行运行事务。

#### 交接依据是状态，不是平台名

一轮事务在两个执行者之间交接时，接手方**不得**依据前一方的口头总结、也不得依据"它是哪个平台"来判断进度。可接受的交接依据只有三类可核对的状态：

| 依据 | 怎么读 | 回答什么 |
|---|---|---|
| **当前提交** | `git log` / `git show <sha>` 读已提交的树 | 哪些统一资产变更已经固定 |
| **尚未消费的包** | `dumps/inbox/` 中未出现在 `dumps/processed/manifest.md` 的包 | 还有哪些输入没有影响任何已提交版本 |
| **尚未投递的投影** | `projections/` 已生成、但对应 `state/endpoints/<id>.md` 中 `projection_delivered: false` 的项 | 还有哪些结果没有回到目标端 |

接手前必须完成：检查事务锁是否已释放、检查工作区是否干净、读取上一轮事务回执的终止状态。**任何一项不满足，先停下并交给用户判断，不得强行接管。**

### 本地知界实例：唯一事实源

每位用户拥有一个本地知界实例。它包含：

- **统一资产**：画像、近期状态、沟通路由、信息源路由和证据；
- **不可变输入**：已导入的各端倾倒包；
- **处理状态**：哪些包已消费、生成了哪个版本；
- **端投影**：为 ChatGPT、Claude.ai 和本地 Agent 准备的材料；
- **审计历史**：由本地 Git 保存的版本、差异和撤回记录。

默认运行不依赖远端仓库。用户可以把本地 Git 连接到私有远端用于备份或跨设备迁移，但这不是当前端接入的前提，也不允许线上端直接写统一资产。

技能代码仓与个人知界实例必须分开。公开的 `Alexu0317-FATHER/contour` 只能存代码和公开文档，不能存用户画像、家庭、健康或私人倾倒包。

### 端适配器：输入与投影通道

端适配器不拥有协调权，只完成两类工作：

- **输入**：读取用户明确指定的会话或本端可见记忆，生成带来源的倾倒包；
- **输出**：接收持锁执行者生成的端投影，让它影响当前上下文，并在平台允许时作为原生记忆的参考材料。

不同端可以使用不同通道，不再强求都接入同一连接器：

| 端 | 输入到本地实例 | 投影送回 |
|---|---|---|
| **ChatGPT 模式** | 在 ChatGPT 模式中用 `@` 运行知界 Skill，读取用户点名的会话 / Project 并生成倾倒包。**能否直接写本地 `exchange/from/chatgpt/` 仍 `[未验证]`**，须先做一次无真实数据的 canary；不成立时回退到"生成文件 → Codex 模式受监督浏览器下载 → 导入" | 优先在 ChatGPT 模式内直接读取投影文件；不成立时由 Codex 模式受监督浏览器上传 |
| **Claude.ai** | Claude.ai Skill 生成 Markdown 倾倒包，由 Codex 模式通过受监督浏览器下载并导入 | Codex 模式受监督浏览器上传端投影，并要求在当前会话或 Project 中使用 |
| **本地 Agent**（Claude Code、VS Code / Zed 中的 Agent） | Skill 把包写入该端专属交换目录 `exchange/from/<endpoint-id>/` | 直接读取 `exchange/to/<endpoint-id>/` 下的端专属投影文件 |

**受监督浏览器是回退桥，不是默认必经路径。** ChatGPT 会话与 Projects 的默认路径是 ChatGPT 模式；只有当 ChatGPT 模式无法完成某一步时，才降级到浏览器下载 / 上传。

浏览器操作是**受监督适配器**，不是稳定后台 API。每次使用必须确认账号、目标会话或 Project、准备上传的文件和最终发送状态；页面变化或工具失败必须显式停下，不能用“应该已经上传”作为成功证据。

## 数据边界

### 统一资产与原生记忆不是一回事

知界统一资产是用户可查看、可修改、可版本化的权威来源。平台原生记忆是统一资产的下游消费者之一，不是权威来源的替代品。

知界可以确认：

- 哪个源包被导入；
- 哪些结论进入了哪个 Git 版本；
- 哪个端投影已经生成；
- 哪个文件已经上传或哪个消息已经发送；
- 某个端的当前上下文是否实际读取了材料。

知界不能仅凭模型口头声称确认：

- ChatGPT 或 Claude.ai 的隐藏记忆数据库已经更新；
- 未来任意新会话一定会召回某条信息；
- 各平台保存了相同措辞或相同数量的记忆。

因此产品目标是“统一资产可靠、投影可追踪、端内使用逐步收敛”，不是“后台记忆完全一致”。

### 记忆、近期状态和权威来源分开

- `profile.md` 保存一年后大概率仍成立的慢变画像；
- `now.md` 保存会变化的用户状态和反向指针；
- `routing.md` 回答“当前怎样沟通、对这个用户什么值得留意”；
- `sources.md` 回答“最新事实应该去哪里查”和“已有知识资产在哪里”；
- 项目进度、任务、日历和业务事实仍留在各自权威系统中。

当问题包含“当前”“最近”“最新进度”“下一步”等快变含义时，Agent 不得只依赖统一记忆或平台原生记忆；能访问权威来源时必须查证，不能把旧摘要冒充现状。

## 本地目录与写入边界

```text
<contour-home>/
├── vault/                              # 本地 Git；每轮只由持锁执行者写
│   ├── config.md
│   ├── profile.md
│   ├── now.md
│   ├── routing.md
│   ├── sources.md
│   ├── evidence.md
│   ├── tests.md
│   ├── state/endpoints/<endpoint-id>.md
│   ├── dumps/inbox/<endpoint-id>/<dump-id>.md
│   ├── dumps/processed/manifest.md
│   ├── projections/<endpoint-id>/
│   └── review/
└── exchange/                           # 不作为统一事实源
    ├── from/<endpoint-id>/             # 各端只能写自己的目录
    └── to/<endpoint-id>/               # 持锁执行者生成，其他端只读
```

`exchange/` 可以位于 `vault/` 之外，或被 Git 明确忽略。其他端生成包时不得直接写 `vault/dumps/`；**本轮持锁执行者**校验成功后，才把包复制进 `vault/dumps/inbox/` 并在同一次事务中登记导入状态。

事务锁位于 `<contour-home>/.contour-transaction.lock`，**在 `vault/` 的 Git 树之外**——它是运行时状态，不进版本历史。所有本地执行者共用这一个路径。

倾倒包一经导入不可修改。更正通过新包表达，删除通过撤回或脱敏流程表达。包只有出现在已提交版本的消费清单中，才算已经影响统一资产。

## 初始化体验

用户第一次说“初始化知界”后，本轮持锁执行者（默认是 Codex 模式）必须按用户能理解的顺序完成以下流程。

### 识别实际组合

先问并自动发现用户准备纳入哪些端，再决定需要什么通道。不得先要求创建 GitHub 账号或私仓。

应区分：

- ChatGPT 模式 + Codex 模式；
- Claude.ai + Codex 模式；
- 一个或多个本地 Agent（Claude Code、VS Code / Zed）+ Codex 模式；
- 线上端与本地端的混合组合；
- 是否真的需要远端备份或跨设备迁移。

已有本地目录、Git 仓库或旧知界私仓时，Agent 先只读检查并提出迁移方案，不重复创建。没有本地实例时，由 Agent 创建目录和本地 Git；只有选择远端备份时，才处理 GitHub 登录、建仓和 push。

### 明确授权和范围

在读取任何跨会话内容前，执行端必须告诉用户：

- 准备读取哪个端、哪个账号、哪个会话或 Project；
- 读取是一次性的、指定范围的，还是后续会重复使用；
- 取得的内容会保存到哪个本地目录；
- 哪些内容可能被送回其他端；
- 哪些动作需要上传、发送或远端写入。

默认只读取用户点名的会话和文件，不以“全面了解”为理由扫描全部历史。登录、验证码、账号授权和敏感范围扩大必须由用户本人确认。

### 收集基线

每个已纳入端都应生成或被读取一次基线：

- ChatGPT 基线在 **ChatGPT 模式**中生成，来源是用户指定的一个或多个会话及其 Project 上下文；
- Claude.ai 基线由已安装的知界 Skill 生成结构化 Markdown 包；
- 本地 Agent 基线由本端 Skill 写入自己的交换目录；
- 已有画像和记忆导出是补充来源，不能冒充某个端的基线。

至少两个不同端的有效基线到齐后，才能把结果称为“跨端统一版本”。只有一个端时可以创建本地草稿，但回执必须写“尚未形成跨端基线”。内容为空的有效基线可以计入，因为“当前没有可输出内容”也是该端的真实结果。

### 合并并建立第一版

持锁执行者校验来源、格式和重复包后，按本文的合并规则生成第一版统一资产，写入消费清单并创建一个 Git commit。第一版成功不以所有端都完成原生记忆吸收为前提。

### 送回并逐端确认

持锁执行者为每个已纳入端生成投影；送回由具备该端通道的执行端完成。初始化回执必须逐端说明：

- 基线是否取得；
- 是否已进入统一版本；
- 投影是否生成；
- 是否已送达；
- 当前上下文是否加载；
- 原生记忆吸收是否可观察。

某个端失败不抹掉其他已完成状态，也不能被压缩成一个笼统的“同步成功”或“同步失败”。

## 日常同步体验

日常同步由本轮持锁执行者完成协调，默认是 Codex 模式。用户可以在 Codex 模式发起，也可以先在某个来源端说“倾倒知界”，再让持锁执行者接手导入。

### 来源端先保护自己的新增信息

在接收本轮新投影之前，来源端先生成或暴露自上次成功采集边界以来的新内容。这样可以降低把上一轮投影再次当作新证据倒回来的风险。

“无变化”不能只与上次统一版本比较。实现必须同时考虑：

- 本端上次成功导出或被采集的位置；
- 已经导入和消费的本端包；
- 上次送给本端的投影；
- 本端能否提供稳定的会话、消息或文件游标。

没有稳定游标时，不得把结果声称为精确增量；应生成带范围说明的快照，由持锁执行者做来源感知的差集和回声消除。

### 持锁执行者导入、合并和提交

一次协调事务按以下顺序进行：

0. **取得事务锁**。锁被占用时只能等待或只读，不得绕过；
1. 检查本地实例、Git 工作区和上次未完成状态；
2. 收集用户本轮授权范围内的新包或新会话内容；
3. 校验并导入唯一、不可变的倾倒包；
4. 读取当前统一资产和所有未消费包；
5. 去重、消回声、处理冲突并生成候选变更；
6. 无有效变化时不升版本、不制造空包，只记录 no-op 回执；
7. 有变化时，把统一文件、消费清单、端状态和投影作为一个事务提交；
8. 重新读取实际 commit 和产物，确认发布内容；
9. 按端送回投影并分别记录结果；
10. **释放事务锁**，并留下终止状态（完成 / 失败 / 放弃）。

本地每轮只有一个规范写入者，因此不再为网页端设计多写者 CAS 发布协议。但**同机的多个本地执行者**——多个 Codex 模式任务、Claude Code、VS Code / Zed 中的本地 Agent——仍可能竞争，必须通过整轮事务锁、干净工作区检查和失败恢复防止互相污染。

### 送回线上端

送回是日常流程的一部分，但不同通道的自动化等级必须如实标记：

- 能用应用内能力完成时，记录目标会话、发送结果和可见消息；
- 需要浏览器时，Codex 模式可以代用户选择文件、上传和发送，但必须让用户确认账号与目标；
- 页面变化、登录失效、上传失败或无法确认发送时，保留待送达状态并告诉用户下一步；
- 只上传文件但没有让端实际读取，不能记为“已加载”；
- 端在当前会话读过文件，不等于后台原生记忆已吸收。

用户不应长期手工复制大段 Markdown。当前能力确实只能手动完成时，执行端应把人工动作压缩为登录、授权或最后确认，而不是把搜索、下载、改名、搬运和状态判断全部甩给用户。

## 合并规则

### 先消回声，再谈证据

上一轮送给某个端的投影，下一轮可能被该端原样输出。重复出现不能自动成为第二份独立证据。持锁执行者必须利用投影记录、来源指针、包标识和采集游标做差集；无法判定时标记不确定，不通过重复次数增加可信度。

### 时间冲突只认条目级依据

倾倒包创建时间、下载时间和导入时间只用于审计，不能证明其中事实更新。可以裁决新旧的依据包括：

- 事实发生时间；
- 用户陈述时间；
- 平台提供的记忆或消息创建时间；
- 明确的 `supersedes`、撤回或更正关系。

没有条目级时间依据的矛盾不得偷偷选一个，进入 `review/` 等待确认。

### 事实冲突与视角互补分开

- 两条信息不能同时为真，且没有足够依据裁决：并列保留证据，正文标记待确认；
- 两条信息可以同时为真，只是来自不同场景：合并成更完整的结论，并保留原始表述和来源。

视角互补是知界的主要价值之一。不同端分别看见用户的一部分，统一资产要把这些部分拼回去，而不是把其中一端覆盖掉。

### 信息分层

每条内容按以下顺序归属：

1. 怎样与用户沟通、什么值得留意 → `routing.md`；
2. 最新事实去哪查、已有资产在哪里 → `sources.md`；
3. 原始材料、来源、冲突和取代关系 → `evidence.md`；
4. 一年后大概率仍成立的提炼结论 → `profile.md`；
5. 会变化或不确定时效的用户状态 → `now.md`；
6. 无法裁决、需要用户确认或失败恢复 → `review/`。

## 状态与回执

以下状态必须分别记录，不能共用一个“已同步”游标：

| 状态 | 回答的问题 |
|---|---|
| 来源已采集 | 本端的新内容是否真的取得 |
| 包已导入 | 内容是否已经进入本地实例且通过校验 |
| 包已消费 | 它是否已影响某个已提交的统一版本 |
| 统一版本已提交 | 权威文件和清单是否已由 Git commit 固定 |
| 投影已生成 | 是否已经为目标端准备材料 |
| 投影已送达 | 文件或消息是否真正到达目标端 |
| 当前上下文已加载 | 目标端是否在当前会话实际读取 |
| 原生记忆已吸收 | 平台是否提供可观察证据；否则只能记“已请求但不可观察” |

这些状态可以同时成立，也可以停在不同位置。例如：“ChatGPT 模式的内容已导入并消费；Claude.ai 投影已生成但上传失败；Codex 模式当前上下文已加载；两端原生记忆均不可观察。”这是合法结果，不能强选一个互斥终态。

### 本地提交回执与端点投递回执必须分开

上表里有两类性质完全不同的回执，**不得合并成一次“成功”**：

| 回执类型 | 由谁产出 | 怎么核对 | 覆盖哪些状态 |
|---|---|---|---|
| **本地提交回执** | 本轮持锁执行者 | `git show <sha>` 可完全离线核对 | 包已导入、包已消费、统一版本已提交、投影已生成 |
| **端点投递回执** | 具备该端通道的执行端（网页端目前是 Codex 模式） | 依赖受监督界面操作，随时可能因登录失效或页面变化停在中途 | 投影已送达、当前上下文已加载、原生记忆已吸收 |

两者可验证性等级不同：前者是确定性的，后者是观察性的。把它们压成一个“已同步”，等于用最弱的那一半冒充最强的那一半。

一次**合法**的终态可以是：

> 本地提交回执 = `<sha>`，由 Claude Code 持锁完成；
> 端点投递回执 = 未产生，投影已生成，等待具备 ChatGPT 通道的执行端送达。

如果某个本地执行者完成了合并和 commit 但没有该端的送回通道，回执就停在“投影已生成，等待送达”。**不得声称目标端已经更新。**

每次运行至少报告：

- 本轮涉及哪些端和数据范围；
- 新增、重复、冲突、跳过和失败分别发生了什么；
- 当前统一 commit；
- 哪些端尚未取得或尚未收到本轮变化；
- 哪些动作需要用户继续；
- 哪些结论只是未验证或不可观察。

## 证据门禁

平台能力结论必须标明日期、账号或产品环境和证据等级：

- `[实测]`：在目标账号与真实工具中完成了所述动作；
- `[官方文档]`：官方明确描述，但尚未在目标账号完成；
- `[用户观察]`：截图或现场操作可见，但复现范围有限；
- `[社区]`：社区报告，只能作为风险线索；
- `[推断]`：由已知事实推导，必须写出推导链；
- `[未查到]`：查过了，没查到相关记载。**这不是“不支持”，只是“没找到证据”**；
- `[未验证]`：尚无足够证据。

**这七类不能互相顶替。** 最常见的三种滑动是：把 `[用户观察]` 写成 `[实测]`（看见界面 ≠ 跑通流程）、把 `[推断]` 写成 `[官方文档]`（推出来的 ≠ 人家写的）、把 `[未查到]` 写成“不支持”（没找到 ≠ 不存在）。`docs/平台能力实测.md` 用的是同一套七类标记，两份文档的定义必须保持一致。

`未找到`、`404`、工具没有返回内容和模型自述都不能单独证明能力不存在。Agent 必须先查官方资料和公开信息，再做安全的只读探测；只有仍无法确认且确实影响产品决策时，才请求用户做最小必要测试。

README 只能把已经通过对应组合验收的能力写成现状。需求目标、官方存在、账号可见、单步工具可用和完整闭环通过是五件不同的事。

## 安全、隐私与删除

- 未经用户明确授权，不读取跨会话内容，不下载文件，不上传或发送投影，不提交或推送远端；
- 只处理用户有权访问的数据，不要求用户提供密码、会话 Cookie 或其他可复用凭据；
- 默认最小读取范围，扩大到整个 Project、账号历史或目录前再次确认；
- 上传前展示目标端、目标会话或 Project、文件名和内容范围；
- 私人数据默认留在本地，远端备份必须由用户主动开启并验证为私有；
- 不主动猜测哪些信息应该删除。用户要求撤回时停止使用并记录取代关系；用户要求清除原文时，单独确认脱敏范围；
- Git 历史、旧克隆、网页端已吸收的记忆和无法定位的转述不能被虚假承诺为已经彻底删除。

## Alex 首个实例与当前验收组合

Alex 的现有私有实例仓属于上一版架构资产。迁移时应先只读检查，再决定把哪个本地 clone 作为新 `vault/`，或把旧仓作为导入来源与可选远端备份；不得让 ChatGPT 或 Claude.ai 继续直接写统一资产。

当前第一条完整验收路线是：

```text
ChatGPT 模式指定会话 ─┐
                      ├─> 持锁执行者导入与合并 ─> 本地 Git commit ─> 本端加载
本地 Agent 倾倒包 ────┘                                        └─> 逐端投影与送回
```

其中：

- **ChatGPT 模式**负责读取用户点名的会话 / Project 并生成交换物，不经过内置浏览器；
- **持锁执行者**（默认 Codex 模式）负责导入、合并、提交与投影生成；
- **投影送回 ChatGPT 端**优先在 ChatGPT 模式内完成；不成立时才降级到 Codex 模式的受监督浏览器上传。

随后增加 Claude.ai Skill → 受监督浏览器下载 → 导入 → 投影上传闭环。它们应共用同一状态机和回执结构，但分别记录通道能力。

验收至少证明：

- 初始化先识别用户已有端、本地目录和旧实例，不再先索要 GitHub 私仓；
- ChatGPT 指定会话能在 **ChatGPT 模式**中被读取并形成有来源的输入，不依赖 GitHub 插件，**也不依赖内置浏览器登录**；
- 未持锁的本地 Agent 只能写自己的交换目录，不能修改统一资产；
- 持锁执行者能导入至少两个端的基线，保留冲突和互补信息并创建第一版 commit；
- 日常无变化不产包、不升版本，已导入未消费内容不会被再次当成新包；
- 投影送回失败、文件已上传但未加载、当前会话已加载但原生记忆不可观察等状态能同时如实报告；
- **本地提交回执与端点投递回执分别记录**，"本地已提交、端点未送达"被承认为合法终态而非失败；
- 完整闭环不需要网页端取得 GitHub 写权限；
- 任一官方能力变化或实测失败都能被记录为证据更新，而不是被技能悄悄绕过。

以下项在通过实测之前**不得写成已验收**：

- ChatGPT 模式能否直接写本地 `exchange/from/chatgpt/` —— `[未验证]`，须先做一次无真实数据的 canary；
- 跨应用事务锁互斥（Codex 模式持锁时 Claude Code 被拒、反之亦然）—— `[未验证]`；
- **倾倒包内容完整性的导入前准入** —— 当前校验脚本只做 schema / 身份 / 位置检查，篡改只能靠脚本外的 SHA-256 比对发现。哈希由谁生成、保存在哪、谁负责在导入前核对，尚未在协议中定死；
- 生产 `skills/contour/` 是否已从 GitHub 多写者协议迁移到本文架构 —— **未迁移**，当前仍是旧协议。

## 与外部记忆服务的关系

Hindsight 等服务提供的是独立记忆基础设施，通常通过 API、MCP 或托管服务完成 retain、recall 和反思。知界选择的是另一条路：利用用户已有的 ChatGPT 桌面应用、本地文件和各平台订阅，维护一套可直接审阅的 Markdown/Git 资产，再把结果投影给现有端。

知界的优势不能写成绝对“免费”：用户仍承担已有订阅、模型用量、安装配置和受监督浏览器操作成本。准确的价值主张是：

- 不要求个人用户再购买一个托管记忆服务；
- 数据默认保存在用户本地，可查看、可迁移、可版本化；
- 不要求每个聊天端都安装同一个 MCP 或拥有 GitHub 写权限；
- 适合已经拥有 ChatGPT 桌面应用、愿意用本地控制面换取数据主权和较低新增现金成本的用户。

如果用户需要无桌面应用、全天候托管、任意应用 API 接入或完全自动化的记忆基础设施，外部记忆服务比知界更合适。知界不应假装覆盖这类需求。

## 非目标

- 不重建一个通用向量数据库或托管记忆 API；
- 不控制、替换或保证各平台隐藏的原生记忆机制；
- 不恢复从未被任何端保留且无法访问的信息；
- 不把 Alex 的个人目录、画像或账号结构固化为公共模板；
- 不接管 Notion、项目日志、任务系统和日历；
- 不把网页自动化包装成稳定后台接口；
- 不让任何两个本地执行者在同一事务内同时修改统一资产；不让任何网页或会话界面修改统一资产；
- 不按平台名或模式名授予 Vault 写入资格；
- 不把内置浏览器登录写成读取 ChatGPT 会话和 Projects 的前置条件；
- 不要求日常运行必须 push GitHub；
- 不把纯网页、无 ChatGPT 桌面应用的用户写成当前受支持对象；
- 不在没有证据时声称某个端已接入、某条记忆已写入或完整流程已通过。
